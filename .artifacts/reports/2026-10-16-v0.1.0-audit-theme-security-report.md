## 7. S5 — remote path construction (Deck REST; no WebDAV ships, plan D1)

**Assembly chain** (every step's encoding behavior):

1. `DeckClient::new` (client.rs:328-353): `Url::parse` → scheme must
   be `http` **or** `https` (:330 → F12-03) → host non-empty (:333) →
   **query/fragment stripped** (:336-337) → trailing slash trimmed
   (:338-343). **userinfo is *not* stripped** → F12-02.
2. `path_prefix` — both scopes `&'static str` (client.rs:25, :186-191).
3. Resource builders — all ~30 `format!("boards/{id}…")` sites
   enumerated (client.rs:370-1250): every dynamic segment is a `u64`
   parameter (`board_id`, `stack_id`, `card_id`, `label_id`,
   `attachment_id`); the `filter.path_segment()` is a `&'static str`
   enum method (model.rs:64-75); the `flag`/`action` sub-path
   parameters are `&'static str` literals at their only call sites
   ("archive"/"unarchive" :1045/:1059, "assignLabel"/"removeLabel"
   :1130/:1146).
4. Final assembly: `base_url.join(&format!("{prefix}/{resource}"))`
   (client.rs:1384-1387) — `Url::join` percent-encodes per RFC 3986
   while parsing; moot here since segments are digits/statics.
5. Query strings: exactly one, `?boardId={board_id}` (client.rs:742-744) —
   numeric.
6. **User content never enters a path or query**: titles/descriptions
   travel only in JSON bodies (`serde_json` → `request.json()`,
   client.rs:1396-1400) and attachment file names only in multipart
   bodies (`multipart_form`, :225-249). The server cannot steer the
   request target through any response-controlled value.

**Traversal**: `download_attachment` returns raw bytes to the caller
(client.rs:677-704) and has **no production consumer** (grep: tests
only) — no server-controlled content is ever written to a local
filesystem path; a malicious title has no path to reach.

**Credentials on the wire**: `basic_auth()` header from the split
`credentials` string (client.rs:1395, :1441-1452) — never in URL or
query. reqwest 0.12.28 (pinned, Cargo.lock:5408-5410) performs no
URL-userinfo handling of its own (only proxy auth), so a
userinfo-bearing `server_url` is neither applied as auth nor stripped
— it just rides the URL (→ F12-02).

**S5 verdict**: structurally sound — path/query provenance is
numeric-or-static by enumeration, user content is body-only, no
traversal surface. Findings: F12-02 (userinfo tolerated), F12-03
(cleartext http accepted silently), F12-07 (WebDAV naming drift,
cross-ref grade).
