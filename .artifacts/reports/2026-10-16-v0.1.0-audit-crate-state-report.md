## 3. Axis E — crate & module factoring (command-loop structure map)

### 3.1 Module inventory vs AGENTS §2

Five src files, 1 220 lines total (plan §2 table verified by
`wc -l`): `lib.rs` (84 — pub surface + the crate contract),
`actor.rs` (836 — the loop, the handle, the envelope),
`core.rs` (204 — private working state + single-advance rule),
`config.rs` (33 — tick knobs), `error.rs` (63 — lifecycle errors).
Every module doc's responsibility claim matches its contents:
semantics live in the domain (`plan_command`, `apply_sync_report`,
`apply_actions`, `due_firings` are all domain imports — actor.rs:22–27,
core.rs:14–17); the crate does channels, sequencing, publish, and
persistence ordering. Manifest verified: production deps = domain,
arc-swap, chrono, tokio, thiserror, tracing; storage is a
dev-dependency (the I1 smoke only) — the lib.rs:14–16 "never depends
on a storage implementation" contract holds. `#![forbid(unsafe_code)]`
(lib.rs:74); SPDX headers on all five src files.

The crate's own contract claims check out: "thin orchestrator"
(lib.rs:17–19) — the only decision-flavored code is persistence
*ordering* policy, each piece citing its design decision in a comment:
`RequestSync` fast path (actor.rs:512–526), the nudge-iff-enqueued
rule (actor.rs:559–572), `append_status_if_changed`
(actor.rs:679–688), `append_validators_if_changed` (actor.rs:694–726,
"phase 4 decision 4"), `note_storage_failure` edge semantics
(actor.rs:755–764), durable-then-notify tick shape (actor.rs:774–806,
"design §6"). That split is principled: these decide *when to write*,
never *what entities mean*.

**No split candidate.** For a 1.2k-line src this is a single-actor
crate whose loop *is* the design (the `#[allow(clippy::too_many_lines)]`
on `run_loop` documents that choice, actor.rs:298–301). §clippy-pedantic
is clean; §churn (107 touches, no src file in the workspace top-30)
shows no extraction pressure. A "no split" verdict is the outcome, with
the one watch-item: `actor.rs` is 68% of the crate and now carries four
concerns (envelope/handle, loop, command application, reminder tick) —
if a fifth select! arm or a second actor family lands, splitting the
tick path into `tick.rs` is the natural first cut (P3, F4-09 adjacent —
recorded here as a fact, not a finding, since no origin axis names a
candidate for this crate).

### 3.2 Command-loop structure map (plan §3.2 deliverable)

`run_loop` (actor.rs:302–478): one `tokio::select!` with `biased;`
(actor.rs:354–355 — deterministic drain order: commands, reports,
system, timer) over four arms, each with a liveness precondition; two
exit routes checked at the top of every iteration.

| Element | Site @ tag | Semantics |
|---|---|---|
| Exit check 1 — drain complete | actor.rs:347–350 | `draining && !reports_open` → `return` (clean stop) |
| Exit check 2 — all sources closed | actor.rs:351–353 | `!draining && !commands_open && !reports_open && !system_open` → `break` (log at :477) |
| Arm 1 — commands | actor.rs:357–401, precondition `commands_open` | `Execute` → decline-with-reply in drain (359–367) else `execute_command`; `Flush` → immediate reply, FIFO barrier (379–385); `ReadState` → `persisted_view` reply (386–388); `AttachConnector` → push to registry or `Draining` receipt (389–399); `None` → `commands_open = false` |
| Arm 2 — sync reports | actor.rs:403–426, precondition `reports_open` | `ingest_sync_report`; `None` → close flag, log drain-complete (:414–419) vs daemon-continues (:420–423) |
| Arm 3 — system events | actor.rs:428–461, precondition `system_open` | `Shutdown` → `draining = true` + `timer_armed = false`, idempotent (429–442); `NetworkLost` (guard `!draining`) → `go_offline` (443–445); `NetworkRestored` (guard `!draining`) → nudge only, no phase guess (446–450); both ignored while draining (451–453); `StorageFailed` never self-acted (454–456); `Closed` → flag; `Lagged` → warn-and-continue (457–460) |
| Arm 4 — reminder tick | actor.rs:463–474, precondition `timer_armed` | `reminder_tick`; re-arm `next_tick = now + cfg.tick`; disabled config never constructs the sleep future (actor.rs:339–344) |
| Drain state machine | actor.rs:331–351, 429–441 | post-`Shutdown`: decline new work (`Execute`/`AttachConnector`), keep ingesting reports until the sync actor's sender drops, timer disarmed outright |
| `storage_failing` edge | actor.rs:323, 759–764 | ok→fail transition fires `SystemEvent::StorageFailed` once per epoch; any successful persistence resets |
| Nudge registry | actor.rs:328, 585–604 | boot entry + attached senders; `Closed` pruned on fan-out; `Full` coalesces; forwarded iff any send lands |

`EngineCommand` surface → handling sites → reply contracts:
`Execute` (actor.rs:46–52) → `execute_command` → `Result<CommandOutcome,
ExecuteError>` ("a received reply implies durability", actor.rs:49–51);
`Flush` (:56–59) → immediate `()` under FIFO (:379–385); `ReadState`
(:65–68) → `Result<PersistedState, RepositoryError>` reflecting every
previously accepted message; `AttachConnector` (:75–80) →
`AttachReceipt::{Attached, Draining}` acked *after* the push (:170–172).

## 9. Axis F — data-model fit (state-side friction facts; no pre-deciding)

  scalar. Friction fact for chunk 16; no action pre-decided.
- **D3/D4 stamps**: `last_updated` is a whole-state mutation stamp
  (core.rs:24, 43) — binary "something changed, when". D3's
  per-occurrence history and D4's undo tree both want per-entity (or
  per-batch) provenance; the stamp cannot provide it. Counter-fact in
  the engine's favor: the single-advance rule (interpret applies
  exactly the persisted batch, core.rs:40–45) means the
  `PersistenceAction` sequence *is* already a faithful journal of
  every mutation — D4's "command journal + inverse synthesis" has its
  raw material in this design; what's missing is only batch identity
  beyond `last_updated`. Friction fact for chunk 16.
- **D5 substrate**: the memory-only `Syncing` transient
  (core.rs:110–119) is correctly kept out of persistence (a reboot
  never advertises a phantom cycle); reminder delivery proofs are
  persisted rows — device-local and merge-friendly, exactly what D5
  asks to keep until a substrate is chosen. No friction.
- **ReadState clone**: `persisted_view()` clones the full state per
  read (core.rs:106–108) and `app()` clones per publish (core.rs:50–60)
  — the sync cycle reads the whole outbox/bindings/validators through

  `'static`-safe, so "no friction", cost pending measurement.
