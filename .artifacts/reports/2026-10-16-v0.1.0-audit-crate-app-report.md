## 2. Extraction verdicts (E axis — up front, decision-grade)

### 2.1 IPC (`src/ipc/`, 5 modules, 1 795 lines; origin §2 E said "~1.5k" — measured per plan D1)

**Coupling inventory (measured, not vibes)**: in-crate consumers —
`client::try_connect` at `main.rs:112,203,230` (transport routing,
`status`, `daemon stop`) and `commands/connect.rs:575` +
`commands/logout.rs` (the best-effort daemon nudges); `server::spawn_server`
at `main.rs:291` only; `protocol` types consumed by `client`, `server`,
`session_ceremonies.rs:229` (`AttachWireOutcome`),
`commands/connect.rs:514`, and `commands/logout.rs:14,227`
(`DetachWireOutcome`); `codec` by `client` + `server` only.
**External consumers: zero** — no crate outside `taskboard-app`
references `taskboard_app::ipc` (grep over `crates/`). One *inward*
coupling works against a clean lift: `ipc/protocol.rs:91` embeds
`crate::commands::status::StatusView` in `Response::Status` — the wire
envelope depends on a commands-module projection type. Tests:
`tests/ipc.rs` (901) + `tests/cli_ipc.rs` (626) move with the module.
The socket naming mirrors the lockfile rule
(`ipc/mod.rs:16-19`, `<db>.sock` sibling of `<db>.lock`).

| Option | Trade-offs |
|---|---|
| (a) Keep in app | Zero work; the only consumer is the binary itself; the module is already self-contained behind 6 call sites; churn is low vs `commands/` (no `ipc/` file in `§churn`'s top 30). |
| (b) Extract `taskboard-ipc` (protocol + codec + client) | Gets a second wire consumer immediately; drags the `StatusView` projection out of `commands/` (or forces a shared projection home) and moves 2 test binaries; no consumer exists today to justify it. |
| (c) Extract all five modules (server too) | Only pays off if a *second daemon-like process* serves the protocol; the server's reason to live is owning the booted `App` (`ipc/server.rs:364`), which is app's core — extraction would invert that dependency. |

**Recommendation: (a) keep in app now; extract protocol+codec+client
(option b) when the kiosk-management wave gives the protocol a second
consumer — that wave is the trigger; do not pre-extract.** Before the
trigger fires, resolve the `StatusView` coupling (it must move with the
protocol or become a shared projection type) — a bounded, mechanical
precondition the module docs already anticipate (ADR 0012's additive
variant policy keeps the surface stable meanwhile).

**Consequences**: deferring costs nothing while app is the sole
consumer; extracting later moves ~2k lines + 2 test binaries in one
mechanical PR. If kiosk-management verbs land in-app first, the later
extraction surface grows — bounded by the module's self-containment,
but the trigger should be evaluated *before* that growth starts.

### 2.2 `completion.rs` (1 593 lines: 802 engine + 791 inline tests)

**Facts**: `pub(crate)` — invisible outside the crate. The engine is
pure by construction (module contract `completion.rs:5-18`: no I/O, no
channels, no runtime, no rustyline types); the only impure act is one
`load_full()` per Tab in the rustyline glue (`completion.rs:766-790`).
Couplings: it walks the clap tree of `crate::cli::Cli`
(`completion.rs:319-357`) — the CLI shape *is* app-owned — and its
selector-parity invariant is tested **against** app's real resolvers
(`completion.rs:1320,1353,1369` call
`commands::tasks::resolve_task/resolve_stack` and
`commands::labels::resolve_label`), not against a re-implementation.

| Option | Trade-offs |
|---|---|
| (a) Stay in app | Zero work; both couplings (clap shape, resolver parity) are intra-crate; the pure core is already hermetically tested. |
| (b) Move to domain | **Refused**: the clap walk drags a CLI/presentation dependency into the purity-bounded crate (AGENTS §2); domain has no selector-by-title concept to host parity against. |
| (c) Own frontend-support crate | Pays only with a second consumer of completion; today there is none. |
| (d) Fold into a future REPL/frontend crate | The natural end state if a second interactive frontend appears; the pure-core/impure-glue split makes the move mechanical. |

**Recommendation: (a) stay in app; fold into a future REPL/frontend
crate if one is ever extracted.** The parity invariant is the real
asset: it is enforced by tests that cross-check the engine against the
resolvers themselves, so semantic drift fails CI regardless of where
the code lives.

**Consequences**: none at v0.1.0. If the resolvers ever move to domain
(see F8-02), the parity tests follow them and completion's remaining
coupling is the clap walk only — the option (d) move gets cheaper.

### 2.3 `commands/output.rs` (565 lines) — the `--json` leak question

**Verdict: correctly placed (adjudicated, not assumed).** The module
contract (`output.rs:1-10`) states the rule ADR 0009 §output fixed:
typed serde projections, *never* the domain's serde shapes, errors as
`{"error":{"kind":…}}` on stderr. Code matches contract: every
projection is an app-owned struct (`TaskRow`, `SyncStatusView`, …);
`SyncStatusView::new` explicitly re-projects the domain status so
domain serde casing never leaks (`output.rs:148-165`); the due-banner
derivation *delegates to domain pure functions*
(`output.rs:57-65` calls `taskboard_domain::overdue_tasks`/`due_soon`
— the semantics live in domain, app renders); the only clock touch is
the render instant (`output.rs:554`, presentation). Formatting for
humans/scripts is the CLI's presentation job (plan D5): no business
logic, no state mutation, no domain-shape leakage. The doc's
"No projection type ever carries a secret" claim (`output.rs:10`) is
**chunk 12's to attack** — recorded, not adjudicated here.

### 2.4 The co-largest-crate signal (14 476 src lines, co-largest with domain) — adjudicated

**Verdict: split-later-with-trigger (recorded as F8-01).** The size
decomposes into app's legitimate jobs: verb surface `commands/` 5 757
(12 modules), frontends `completion.rs` + `repl.rs` + `repl_history.rs`
+ `ui.rs` 3 367, foundation `config.rs` + `bootstrap.rs` +
`secrets.rs` + `lockfile.rs` + `notifications.rs` +
`session_ceremonies.rs` 2 718, IPC 1 795, binary glue `main.rs` +
`cli.rs` + `lib.rs` 839 — the per-file totals sum exactly to 14 476,
of which 3 054 lines are inline `#[cfg(test)]` tests across 19 files
(the *logic* total is ≈11.4k).
No module is misplaced (§3 scan), the three named extraction candidates
are each self-contained with clean seams, and churn concentrates in the
dispatcher (`§churn`: `commands/mod.rs` 36) — expected to churn with
the verb surface it routes. A split today would create crates whose
only consumer is the binary they were extracted from.

**The triggers** (evaluate at wave entry, not on a timer): kiosk
management / a second wire consumer ⇒ IPC extraction (§2.1); a second
interactive frontend ⇒ REPL+completion crate (§2.2); a second
projection consumer ⇒ `output.rs` promotion to a shared home. Until one
fires: don't split.

## 5. F — data-model fit (app-owned shapes only)

- **`AppConfig`** (`config.rs:62-327`): every section
  `deny_unknown_fields` (`config.rs:99,139,152,172,217,257,321`) —
  the secret-free-by-construction guarantee is structural (a `token`
  key cannot decode). For the named waves: multi-board (D2) needs no
  config change (the binding lives in the db, not the config —
  `[storage] db_path` is already per-database); a kiosk deployment
  profile would extend `[ui]`/`[app]` additively. No friction found.
- **`CommandError`** (`commands/mod.rs:84-215`): F8-06 — the
  single-board invariant is baked into variant names/payloads
  (`BoardAlreadyBound { current }` `:108`, `LocalBoardExists` `:178`,
  `NoBoard` `:149`); the D2 wave widens these into per-board facts.
  Extensibility is already paid for: `error_kind()`/`error_detail()`
  are exhaustive matches the compiler forces new variants through
  (`:245-304`).
- **IPC envelopes** (`ipc/protocol.rs:17-186`): versioned with an
  explicit additive-variant policy (two amendments already shipped:
  `DetachConnector` `:40-53`, `AttachConnector` `:54-67` — "no version
  bump for additive changes"); the `VersionMismatch` response is
  deliberately version-less so any client can parse it (`:113-118`).
  The attach request's key set is pinned by a structural test so no
  future field can carry a secret silently (`:296-325`). Kiosk
  management verbs land as additive variants — the envelope shape will
  not force awkward flow. The `StatusView` embedding (§2.1) is the one
  coupling to unwind before extraction.
- **`repl_history` format**: rustyline's own line-per-entry text file,
  self-healing on corruption (`repl_history.rs:9-17`) — no app-owned
  schema, nothing for D-waves to fight.
- **Lockfile/socket naming contracts**: `<db>.lock` (`lockfile.rs:133`)
  and `<db>.sock` (`ipc/mod.rs:28-41`) are per-database — multi-board/
  multi-db safe by construction. Windows pipe names are
  content-hash-derived with a pinned FNV-1a (`ipc/mod.rs:43-92`) so
  separately-built client/daemon agree. Clean.

### 6.1 color-eyre confinement (verified by exhaustive grep)
