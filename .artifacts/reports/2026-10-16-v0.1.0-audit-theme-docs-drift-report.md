### 2.3 The ownership sentence (S1/S2 adjudication)

Doc (:137–141): *"All inter-actor channels — the system broadcast,
both sync mpsc pipes, and the storage/engine command inboxes — are
bootstrap-created and owned by `taskboard_app::bootstrap` (ADR 0008);
actors receive their halves as injected constructor arguments and
never construct channels between themselves."*

Code (chunk 2 §6, verified): the system broadcast and both sync pipes
**are** bootstrap-created (bootstrap.rs:568–570) — but the two
command inboxes the sentence itself enumerates are not: the engine
inbox + SIG bus are constructed in `spawn_state_engine`
(state/actor.rs:259–260, the state crate) and the storage inbox in
`spawn_storage_actor` (storage-sqlite/actor.rs:85). Off-bootstrap
constructors additionally include the UI-command channel (ui.rs:179),
the IPC inbound + stop watch (ipc/server.rs:155–156), and the REPL
handshake pairs (repl.rs:176–177, :293, :377). The second half of the
sentence holds — chunk 2 confirmed no actor constructs channels
*between themselves*; every off-bootstrap constructor sits in a
spawn/hand-over function the app layer calls. The sentence is factually
wrong for two of its four enumerated families and for the forwarder
it elsewhere calls "bootstrap-owned" (:105–106, :122) while naming the
correct path `taskboard_app::ui::spawn_ui_command_forwarder` in the
same sentence (spawned at ui.rs:180 in `run_desktop`) → **F15-02**
(P2; chunk 2 §11.1 called it refinement material — the mechanism and
the injected-halves invariant are right, the creator location is
wrong).

## 6. ADR-0013 resolution (the dispatch's named investigation)

**Verdict: the 0013 gap is an execution accident, not a withdrawn
decision.** "Withdrawn" would require evidence a decision to abandon
was made and recorded; the trail shows the opposite — a
decision-complete draft whose formalization step was believed done.

Evidence chain (all ≤ the tag):

1. **No file ever existed, on any branch**:
   `git log --all --oneline -- 'docs/adr/*0013*'` → empty;
   `git log --all --diff-filter=A --name-only -- docs/adr/` → zero
   0013 entries among all ADR paths ever added.
2. **A complete draft was written and approved**:
   `.artifacts/plans/2026-10-12-reminders-design-plan.md` §12
   "Draft ADR 0013 (formalized by stage 2)" (:699) with full ADR text
   — "ADR 0013: Reminders — Local Due-Anchored Rules, Engine-Tick
   Evaluation, Ported Delivery" (:702) — and an explicit stage-2
   checklist item "formalize ADR 0013 with the §13 resolutions"
   (:842). The round's work-item table (:788) marks the formalization
   item done ("✅") — the step was *believed* executed, which is what
   makes this an accident rather than a rejection.
3. **The gap was later discovered and deliberately routed around**:
   `.artifacts/plans/2026-10-14-gui-phase7-design-plan.md:102–108`
   records "0013 is reserved-but-unlanded … the 0013 gap is recorded
   as bookkeeping debt", and its Q21 decision (:811) chose UI ADR =
   **0015**, explicitly rejecting *reuse* of 0013 — i.e. the number
   stays reserved.
4. **The shipped ADR set itself records the reservation** (in-tree,
   found by the corrected §5 sweep): ADR 0015:19–23 states "The ADR
   numbering skips 0013 deliberately: that number is reserved by the
   reminders design round … It is not a withdrawn or accidental
   number, and it was not reused here to keep the reservation
   honest." Its "not withdrawn or accidental" phrasing refers to the
   *reservation* being deliberate; the *file's* non-landing remains an
   execution accident (item 2's checklist was marked done). The two
   texts agree: deliberate reservation, accidental non-landing.
5. **The debt is tracked**: backlog entry "[2026-10-14] Formalise ADR
   0013 (reminders) from the reminders design plan §12/§13"
   (`.artifacts/taskboard-potential-improvements-backlog.md:2729`),
   which itself states "the ADR file never landed — the number is
   reserved by that round, deliberately not reused".
6. **No dangling references**: the only 0013 mention in `docs/` is the
   ADR 0015:20 note above; the three guides and the CHANGELOG contain
   zero 0013 mentions and reference no non-existent ADR (§5 sweep).

**Consequence (the finding)**: the reminders subsystem shipped whole —
due-anchored rules, engine-tick evaluation, ported delivery via the
notifier (state/actor.rs:463 reminder-tick arm, :832 notification

record, while plan prose marks the formalization done. → **F15-16**
(P2). Proposed action echoes the backlog entry (formalize from the
plan's §12/§13 text); the backlog file itself is untouched here
(conv 7). Numbering question answered: **0013 must not be reused** —
the phase-7 Q21 "do not reuse" decision stands (recorded

gap exactly as tracked.
