## Axis F — data-model fit vs D1–D6 (friction walkthrough; no choices made)

- **D1 (field-carrying merge strategy)**: the schema carries per-field
  `ck_*` clocks (0001_init.sql:40–62), but writes are whole-row upserts
  of all 21 task columns (repo.rs:800–847). A field-carrying writer
  would need per-field statement granularity; the current
  partition-loop `execute_batch` makes that awkward only in statement
  count, not in structure (each upsert is already per-entity and could
  become per-field without reordering). Friction: moderate, mechanical.
  Recorded; the D1 decision itself is **chunk 16's**.
- **D2 (multi-board)**: `sync_status` is a hard singleton —
  `CHECK (id = 1)` (0001_init.sql:103), seeded idle
  (0001_init.sql:109), read `WHERE id = 1` (repo.rs:492–501), written
  `VALUES (1, …)` (repo.rs:953). N boards syncing independently would
  need a keyed table + codec/migration work; the domain `SyncStatus`
  side is **chunk 4's** fact. Friction: real but localized to one
  table + two statements. Same for validators: keys are already
  per-board (`stacks:<board>`/`archived_stacks:<board>`, codec.rs:222–223;
  roundtrip test roundtrip.rs:479–494) — multi-board validators need no
  schema change, only more keys (codec.rs:470–474 documents the
  free-form TEXT property).
- **D4/D5 (undo / app-data sync substrate) + kiosk disk envelope**:
  tombstones are `deleted` flags + `ck_deleted`, retained forever
  (0001_init.sql:6–8; no entity `DELETE` anywhere in execute_batch —
  the only deletes are join rows, outbox rows, reminder rows). Growth
  is bounded by user activity, not by a GC. Retention adjudication is
  **chunk 10's** (ADR 0005); recorded here as the storage fact.
- **Edge-behavior facts verified and classified** (plan §2.3): all
  three documented lossy conversions exist as described — `pending_ops`
  saturation (repo.rs:623), `remote_col` u64→i64 saturation at
  `i64::MAX` (codec.rs:317–322), reminder `offset_seconds` whole-second
  truncation toward zero (repo.rs:980–992, `num_seconds()`; negative
  offsets guaranteed by the domain constructor — decode rejects
  positive/overflow, repo.rs:357–361). All three are unreachable at
  realistic scale and each carries a doc comment: accepted-risk facts,
  **F5-08** (P3, so they stay known).
- **Never-ORDER-BY-timestamps rule** (0001_init.sql:5–7): audited —
  `load_inner` runs 12 SELECTs; 11 of them carry an `ORDER BY` (the
  singleton `sync_status` lookup returns one row and orders nothing),
  and all 11 order by `id`, `op_seq`, `key`, `rule_id`, `(task,
  label)`, `(reminder, occurrence)`, or `task_id` (repo.rs:421, 433,
  445, 462, 469, 478, 486, 507, 518, 529, 536 — the complete set).
  **Compliant; zero violations.**

## Axis I.4 — error taxonomy (sqlx wrapping)

Two clean construction/port layers, `thiserror` only, `color-eyre`
absent from the crate (grep; AGENTS §4 honored):

- `OpenError::{Connect, Migrate}` (error.rs:7–15) — construction-time
  only, `#[source]` sqlx errors preserved.
- `RepositoryError::{Unavailable, Corrupted}` (domain
  persistence.rs:50–57) — the port's two classes; retry semantics
  documented domain-side (`Unavailable` transient, `Corrupted` not
  retryable) and preserved by the mapping.
- `repo_error` shape-match (error.rs:25–43): `ColumnDecode`/
  `ColumnNotFound` → `Corrupted`; the four constraint-violation kinds
  (`Unique`, `ForeignKey`, `NotNull`, `Check`) → `Corrupted`;
  everything else → `Unavailable`. Match is on error **shape**, never
  message text (AGENTS §5-compatible); the orphan-rule rationale for
  not using `From` is documented (error.rs:17–23). Arms verified
  against the domain contract.
- `stmt_error` logs the source at debug before collapsing
  (repo.rs:172–175) — a bug-report log localizes the failing SQL even
  though the port reply is coarse; the coarse port variant is the
  contract, diagnosability is preserved. Verdict: no stringifying
  anti-pattern; the known coarseness ("FK violation vs damaged data"
  both → `Corrupted`) is already a backlog entry — chunk 17's, not
  re-litigated here.
- `CodecError` is a unit struct (codec.rs:20–22) — every decode failure
  collapses to `Corrupted` with the offending value visible only in the
  failing statement's debug log. Typed-outcome discipline is otherwise
  followed (tests assert `matches!(…, Corrupted)`, e.g.
  roundtrip.rs:379–448). Fact recorded; no finding beyond **F5-07**
  (the decode fns' arity-trusting indexing, cross-ref chunk 9 for the
  daemon-reachable-panic lens I.3).

## Axis H — duplication & simplification

Sonar `§sonar`: the crate is duplication-clean (no storage file among
the 14 duplicated files, 0 blocks) — cited, no manual duplication
mining beyond the plan's named seams.

- **(a) serde-wire ↔ codec-text mirror** (codec.rs:4–9): the crate
  hand-writes TEXT forms that mirror domain serde forms for op tags
  (codec.rs:41–58, 123–159), sync phase/error kinds (codec.rs:163–184,
  193–215), and validator keys (codec.rs:219–246) — two encodings of
  the same knowledge. Notably `ReminderRef` already shows the
  alternative pattern: the domain owns the text form and the codec
  merely delegates (`reminder.text_form()`/`parse_text_form`,
  codec.rs:251–262). Sketch for unification: give `LocalOp`,
  `SyncPhase`, `SyncErrorKind`, `ValidatorKey` the same domain-side
  `text_form`/`parse_text_form` pair (serde can then derive from the
  text form), collapsing codec.rs to delegation like the reminder refs.
  Trade-off: moves the stored vocabulary into domain (it already owns
  `LocalOp`, so the tags are domain vocabulary anyway). **F5-10** (P3,
  improvement candidate).
- **(b) clock-parse boilerplate**: `.parse().map_err(|_|
  RepositoryError::Corrupted)?` appears 14× in the decode mappers
  (stack ×3 repo.rs:212–223, task ×8 repo.rs:261–292, label ×3
  repo.rs:315–326). A 4-line `decode::clock(&str)` helper next to the
  existing `decode::uuid`/`decode::remote_opt` (repo.rs:157–167) would
  remove all 14. Marginal (each site is 3 lines and greppable), but
  the helper has precedent one struct above — folded into F5-10's
  simplification pass as a cheap companion (S).
- **(c) the four `#[allow(too_many_lines)]`** (repo.rs:65, 229, 406,
  682) + `#[allow(must_use_candidate)]` (error.rs:24) +
  `#[allow(struct_field_names)]` (codec.rs:62) — matches the baseline
  `§clippy-pedantic` inventory (6 scoped allowances). Each carries a
  justification comment; the length rationale ("the order IS the
  design", repo.rs:682) is genuine for execute_batch; of the six, two
  carry comment debt — one justification has a stale count (**F5-06**)
  and one fn duplicates its rationale inline (**F5-04**).
  No concrete replacement exists for any → no removal findings.
