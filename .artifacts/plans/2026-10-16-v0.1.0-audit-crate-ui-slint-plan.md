## 3. Decisions (open questions resolved at planning time)

- **D1 — unsafe census scope and grep pattern.** Census target = every
  `.rs` file the crate compiles from its own sources: `src/**`,
  `tests/**`, `build.rs`. Pattern: `grep -rnw unsafe` (word-boundary, so
  `unsafe_code` in the lib.rs doc note does not mask a real hit), then
  manually drop pure comments. Slint-*generated* code is **out of
  line-by-line scope** — it is upstream's code, characterized at the
  mechanism level instead (D2's experiment shows where it enters).
  Expected outcome per orientation: **0 hits**; the report states the
  count and the proof, not just "none found".
- **D2 — evidencing the ADR 0003 rationale (the forbid experiment).**
  The claim "Slint's generated rendering code requires `unsafe`" is
  converted from doc assertion to evidence by a scratch experiment in
  `/tmp` (never in the repo): copy the workspace to
  `/tmp/taskboard-ui-audit/`, insert `#![forbid(unsafe_code)]` at the
  top of the copied `crates/taskboard-ui-slint/src/lib.rs`, run
  `cargo check -p taskboard-ui-slint` there, and record the errors
  (expected: `unsafe_code` forbidden-lint errors pointing into the
  `include_modules!` expansion). Commands verbatim in the report
  method; time-boxed 15 min; a clean pass (no errors) would itself be
  a finding (the exemption would be unnecessary — see D3's proposal).
- **D3 — per-block verdict rubric (and the zero-hit continuation).**
  Every census hit gets exactly one verdict: **Slint-generated-bound**
  (inside the `slint::include_modules!()` expansion), **Slint-API-bound**
  (a call to an `unsafe fn` the slint API exposes, no safe wrapper
  exists — cite the API), or **avoidable-with-sketch** (finding: safe
  alternative sketched, conv-4 format). With the expected zero hits,
  the axis's decision-grade output becomes the **guarantee-form
  proposal**: today *nothing* prevents future hand-written unsafe. The
  proposal to write (implementation-ready, not implemented):
  crate-level `#![deny(unsafe_code)]` (deny — unlike forbid — is
  locally overridable) plus a dedicated
  `#[allow(unsafe_code)] mod generated { slint::include_modules!(); }`
  seam module, so the compiler confines unsafe to exactly that seam;
  feasibility of wrapping `include_modules!` in a module is verified
  against the pinned Slint 1.18.1 docs/source during execution (the
  generated module names must not collide with `pub mod` names at
  `src/lib.rs:16–27`); fallback option if wrapping is unsupported: a
  CI grep check (pattern from D1) asserting zero hand-written unsafe.
  Both options presented with trade-offs; exactly one recommended.
- **D4 — dumb-client verification procedure** (yardstick: AGENTS §2
  "cannot depend on IO crates; presentation logic only" + ADR 0015 D1):
  (1) *manifest level* — classify every dep in `[dependencies]`,
  `[build-dependencies]`, `[dev-dependencies]` as IO / non-IO, with
  the sanctioned exceptions named (`tokio` = channel fabric per AGENTS
  §3, sync types only — verified by grepping every `tokio::` use site;
  `chrono` = display arithmetic; dev-only `png`/`serde` are test-harness
  concerns, out of the shipped surface); (2) *state-mutation level* —
  grep `\.store(`, `\.rcu(`, `ArcSwap::from` over `src/` and `tests/`,
  adjudicating every hit: **shipped-code** hit = finding; `#[cfg(test)]`
  -gated or `tests/` hit = sanctioned injection seam (planning-time
  facts: the only src hits are `lib.rs:618` inside
  `mod keymap_adapter_tests` (399–629) and `lib.rs:766` inside
  `mod view_component_tests` (632+); tests hits are harness fakes);
  the rubric distinguishes `AppState` mutation (forbidden) from
  UI-local presentation state (`view_state.rs`, widget properties —
  allowed); (3) *business-logic level* — vocabulary scan for
  persistence/merge/scheduling logic (`persist`, `commit`, `merge`,
  `write`, `save`, fs/net IO: `std::fs`, `std::net`, sockets —
  planning-time grep: zero IO hits in `src/`).
- **D5 — `slint::testing` usage map.** Inventory what
  `tests/support/driver.rs` uses from `i_slint_backend_testing` (event
  injection, element access — name the exact APIs), which test files
  ride it (`journeys.rs`, `golden_visuals.rs` via the support harness),
  how elements are addressed (ADR 0015 D5 claims accessible role/label),
  and the pin discipline (`tests/pin_guard.rs` T1 equality vs root
  manifest `slint = "1.18.1"` / `i-slint-backend-testing = "=1.18.1"`).
  ADR 0015's "no public `slint::testing`" is recorded as context fact;
  docs adjudication is chunk 15's.
- **D6 — theme/token structure inventory.** Enumerate the globals in
  `ui/theme.slint` (colour/text-role/spacing), map each enforcement
  layer: `scripts/check_slint_tokens.py` (rules 1–3: literal colours /
  font attributes / px-spacing outside theme.slint) wired at
  `.github/workflows/ci.yml:48–54` with `--self-test`; `src/token_tests.rs`
  (14 fns, `#[cfg(test)]` — which run lane covers them); the
  contrast-over-token-pairs check ADR D2 promises (identify carrier:
  token_tests vs script). Verdict per ADR claim: enforced / partially
  enforced / aspiration, with evidence.
- **D7 — mutant-evidence status.** ui-slint has **no** mutant evidence
  (not in the weekly domain+state sweep; no one-off in `§mutants`).
  The B-axis therefore reasons from the risk map (which ui behaviors
  would be worst to break: keymap resolution correctness, action
  dispatch integrity, state projection fidelity, pin guard) plus `§cov`
  as a negative signal, and states this absence explicitly — mirroring
  the chunk 5/6 fallback discipline.
- **D8 — churn narrative.** The dispatch chunk description expected a
  "young crate — low churn". The baseline contradicts it: 160 crate
  touches (2nd of 6), `lib.rs` = 20 commits (2nd-highest file
  workspace-wide). The report records reality and characterizes the
  `lib.rs` churn (commit subjects via
  `git log --oneline v0.1.0 -- crates/taskboard-ui-slint/src/lib.rs`)
  as a refactor-risk signal — the expectation is corrected, not
  followed.
- **D9 — E-axis extraction question for this crate.** The origin names
  no extraction candidate inside ui-slint, but `actions.rs` +
  `keymap/*` are pure, slint-free modules (verified at planning time:
  imports are `std` + `crate::actions` only) that a second frontend
  (web dashboard per origin §1, or daemon-IPC kiosk clients) could
  want. The checklist evaluates the candidate at the decision-grade
  bar (options / trade-offs / one recommendation / consequences for
  the named waves), with the default expectation "keep in place —
  extraction has no second consumer yet" unless the walkthrough shows
  concrete friction.
- **D10 — findings discipline.** IDs `F7-NN`, conv-4 format; P0–P3 per
  origin §3; every claim cites `file:line` @ v0.1.0 (the worktree is
  the tag tree), a workflow path, or a baseline §anchor; out-of-scope
  improvement ideas become P3 findings, never backlog edits (conv 7);
  the report ends with the axis coverage table including **O** (conv
  5). Renderer/performance verdicts are cross-refs to chunk 13, never
  adjudicated here; doc-drift adjudication is chunk 15's.

## 4. Axis O — unsafe & boundary enforcement (this chunk's headline)

### 4.1 Unsafe census (exhaustive)

1. Run the D1 grep over `src/**`, `tests/**`, `build.rs`; record the
   raw count (comments included) and the adjudicated count.
2. For every adjudicated hit: `file:line`, enclosing function/module,
   verdict per the D3 rubric, and (only for avoidable) the safe-sketch.
3. Run the D2 forbid experiment in `/tmp`; record the outcome as the
   evidence that the exemption is (or is not) currently warranted.
4. Verify the licensing/yardstick side-facts: `#![forbid(unsafe_code)]`
   absent here and present in the other five crates (grep
   `forbid(unsafe_code)` across `crates/*/src/lib.rs`); AGPL headers
   per §2.
5. Write the D3 guarantee-form proposal (deny+allow-seam vs CI grep),
   feasibility-checked against the pinned Slint version, with one
   recommendation.

### 4.2 Machine-checkable boundary proposal (proposal only)

The proposal must be implementable by a remediation agent without
re-design: exact bans, exact config surface, exact CI steps.

1. Establish the mechanics honestly: cargo-deny `[bans]` are
   **graph-wide**; a per-crate rule ("domain must not depend on tokio")
   is not directly expressible in the shared `deny.toml` (current
   `[bans] deny = []` at `deny.toml:89–94`). Verify against cargo-deny
   docs (version per `§env` era) that `cargo deny check
   --manifest-path crates/taskboard-domain/Cargo.toml` scopes the
   dependency graph to that member's subgraph — a per-boundary config
   (e.g. `boundaries/deny-domain.toml`) then bans the forbidden set for
   exactly that root. (Scratch-verify in `/tmp` if docs are ambiguous;
   proposal-only, nothing lands.)
2. **Domain purity bans** (yardstick AGENTS §2): deny `tokio` (any
   async runtime), the net stack (`reqwest`, `hyper`, `tonic`,
   `tokio::net` carriers), UI (`slint`), persistence (`sqlx`,
   `rusqlite`), plus `arc-swap` (state-engine-owned). Allowlist = the
   tag's actual domain deps (serde, chrono, uuid, thiserror, tracing,
   optional proptest) — cross-checked so nothing legitimate breaks
   (prompt 7.3's review criterion). Note dev-dep and feature scoping
   (`--edges normal`; `proptest` is feature-gated).
3. **UI IO bans** (secondary, same mechanism): for
   `taskboard-ui-slint`, ban the IO crates the dumb-client rule
   forbids (reqwest/sqlx/hyper/…), allowlisting the tag's actual set.
4. CI wiring proposal: where the check steps land in
   `.github/workflows/ci.yml`, cost (seconds), and failure modes;
   explicitly *not implemented* in this chunk (read-only discipline).
5. State the residual gap the bans cannot cover (code-level rules like
   "UI never mutates AppState" stay convention + review — say so; the
   D4 scans are the audit-time answer, a lint/AST check could be a P3
   finding idea).

## 8. Effort, time-boxes, risks

- **Stage 2 effort**: ~½–1 day agent-assisted (dispatch sizes the
  chunk M). Time-boxes: forbid experiment 15 min; boundary-mechanics
  scratch verification 20 min; `view_state.rs`/`lib.rs` read-through
  the largest single cost (~2.3k lines combined); snapshot/preset
  breadth verdicts 20 min each.
- **Risks**:
  - The census's likely zero-hit could read as an empty axis —
    mitigated: the forbid experiment, the guarantee-form proposal, and
    the boundary proposal are the decision-grade substance (dispatch
    acceptance demands exactly that).
  - cargo-deny per-crate scoping must be mechanics-verified before the
    proposal commits to it (D4.1 scratch check) — otherwise the
    proposal could recommend a non-expressible config.
  - Wrapping `include_modules!` in an allow'd module may be
    unsupported by slint 1.18 codegen (module-name collisions) — the
    proposal carries the CI-grep fallback, so feasibility risk does
    not block a recommendation.
  - The crate's `.slint` sources are only audited via their Rust seams
    and the token lint (no visual adjudication here); renderer and
    repaint verdicts stay chunk 13's — cross-refs only.
  - Churn contradiction (D8) — none of the §churn facts may be
    smoothed to match the dispatch's "low churn" expectation.
- **Gates**: docs-only diff (plan + report, conv 8); pre-commit
  fmt/clippy hooks run on commit; stage 2 runs the applicable gate
  suite per dispatch §1.4; no push, no PR (stage 3 ships).
