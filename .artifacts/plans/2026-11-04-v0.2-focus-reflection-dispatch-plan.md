**Dependency graph**: chunks 1–2 are docs/research and parallel to
everything. 3 → 4 (shared ui-slint territory: `presentation.rs`,
`models.rs` push pass, review/today surfaces — serial by default; if
run concurrently, the later starter rebases onto the landed one). 5 →
6 (focus config + settings territory). 7 independent. 8 last and
optional. **Default dispatch order: 1, 2 (parallel) → 3, 5, 7
(parallel) → 4, 6 → 8.** Nothing here waits on the parallel
`nextcloud-files-sync` milestone; chunk 1's contract (impl-plan §3) is
the only acknowledgment it gets.

**Dispatch mechanics**: one agent session per prompt, in order
(N.1 → N.2 → N.3 within a chunk); independent chunks may run
concurrently as separate sessions; never two agents share a worktree.
Every chunk works in `../taskboard-WT-<branch>` next to the project
root (AGENTS §8), branched off the then-current `main`, no PR ever
stacked. **Branch names are never reused after their PR lands**
(AGENTS §8, issue #415): a resume/second round of a chunk works on
`<branch>-v2` (or re-branches off the fetched `origin/main`), never on
the landed branch — the doctor treats any worktree whose `HEAD` is
fully contained in `origin/main` as disposable. Create worktrees with
`git worktree add -b <branch> ../taskboard-WT-<branch>` (never
`git worktree add <path> main`). Disk hygiene (AGENTS §8 worktree
lifecycle): any agent creating or recreating a worktree runs
`scripts/worktree-doctor.sh` from the main checkout first — nonzero
exit (free disk below the floor) stops the chunk; stage 3 removes the
worktree as its final handoff task.

**Shared execution model** (binding for every chunk):

1. **Stage 1 — planning agent**: creates the worktree
   `../taskboard-WT-<branch>` on a new branch off the current `main`,
   writes the TDD-first plan at
   `.artifacts/plans/<today>-<topic>-plan.md` in the house `[Plan]`
   style, resolving every open question with a recorded decision,
   commits it (`docs(plan): …`). No implementation, no push. Origin
   sections marked normative are binding; deviations need a recorded
   reason. *(Chunk 1's stage 1 IS the design round — its "plan" is the
   design-round doc in the DR-5 house style, with a §4-style decision
   table; its stage 2 exists only if the user's review requests
   amendments.)*
2. **Stage 2 — implementation/execution/research agent**: continues in
   that worktree (recreates it on the branch if missing — if the
   branch or the worktree path's PR already landed, create
   `<branch>-v2` instead per AGENTS §8; never `git worktree add <path>
   main`), executes per the approved plan — implementation: TDD, every
   commit standalone (rebase-merge hygiene), full AGENTS §10 gate
   suite green through `scripts/run-quality-gates.sh`; research: the
   experiments and the deliverable report. Does **not** push or open a
   PR. Reports deviations.
3. **Stage 3 — review agent** *(protocol amended 2026-10-18)*:
   **begins by rebasing onto `main`** — `git fetch origin --prune`,
   rebase the branch onto `origin/main` (AGENTS §8's rebase dance:
   drop already-merged duplicate commits; resolve only real
   conflicts), push `--force-with-lease` if the rebase rewrote
   history — then reviews the entire branch diff versus the
   **post-rebase** base against the chunk's acceptance criteria +
   AGENTS rules **plus the applicable mandate below**, re-runs
   whatever gates apply, implements fixes for every finding on the
   branch (amend/reword, never duplicate-subject fixups). Its last
   tasks are shipping: push the branch, open the PR to `main` with
   `gh`, watch `gh pr checks --watch` to completion — any failing
   check is a finding; diagnose, fix, push `--force-with-lease`,
   repeat until green — **then verify the PR's merge state**: `gh pr
   view --json mergeStateStatus` must report `CLEAN`; `BEHIND`/`DIRTY`
   ⇒ rebase onto `origin/main`, push `--force-with-lease`, let the
   checks re-run, repeat; any other state ⇒ diagnose before handing
   off. **Then teardown**: remove the now-disposable worktree — from
   the project root, `git -C /home/viktoria/src/taskboard worktree
   remove --force ../taskboard-WT-<branch>` (absolute anchor per
   AGENTS §8 — never a bare relative path, which resolves against
   whatever cwd the session happens to be in and can name a
   neighbour's worktree; everything precious is pushed; a later round
   that resumes the chunk recreates it on a fresh branch). Confirm via
   `git worktree list` that the removed path was the intended one. The
   handoff contract is "PR open + checks green + merge state `CLEAN` +
   worktree removed" so the user's merge needs no additional rebase
   and the chunk leaves no 36–55G of build output behind. Reports a
   verdict. Never merges; never touches `main`. (`main` is
   branch-protected — merges happen on GitHub by the user, after the
   required checks pass.)

**Code-quality mandate** (stage 3, implementation chunks 3–8 — copied
verbatim from the house dispatch protocol):

> Beyond functional review, evaluate (a) code quality: naming, comment
> discipline (comments state constraints, not narration), idiomatic
> use of the approved stack, no dead code or speculative generality,
> test quality per AGENTS §5; (b) the Single Responsibility Principle:
> the crate-role boundaries of AGENTS §2 are the SRP line — a boundary
> violation is an SRP violation; (c) a single level of abstraction per
> function body: a function either orchestrates named operations or
> works in primitive data, never mixes. Findings are fixed on the
> branch like any other finding.

**Evidence & artefact mandate** (stage 3, research/docs chunks 1–2):

> Every factual claim carries evidence (the command run + observed
> outcome, or a verifiable source + what it states) and experiments
> are reproducible from the report's method section; recommendations
> are decision-grade (options, trade-offs, exactly **one**
> recommendation, consequences for later work); repo hygiene (scratch
> code and captured payloads never land — evidence is excerpts inside
> the report; the PR diff is exactly the chunk's artefacts); scope
> discipline (out-of-scope ideas go to the backlog per its template,
> not into the report).
