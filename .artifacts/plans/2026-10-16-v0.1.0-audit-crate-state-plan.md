### 3.1 ArcSwap write-ownership verification (AGENTS §2/§3 — the acceptance headline)

The yardstick: `taskboard-state` "owns the write side of
`ArcSwap<AppState>`" (AGENTS §2) and "State → UI (reads)" is lock-free
via ArcSwap (AGENTS §3). **Any other writer is a finding** (dispatch
§5). The claim must rest on an **exhaustive enumeration**, not a
sample (prompt 4.3 review criterion).

Procedure, two independent sweeps whose results must cross-check:

1. **Constructor sweep** — `grep -rn --include='*.rs' 'ArcSwap' crates/`
   → classify *every* hit: file:line, which `ArcSwap<T>` type (by
   declaration/import), construction vs mere type mention, owning
   crate, `#[cfg(test)]`-gated or not.
2. **Writer sweep** —
   `grep -rnE --include='*.rs' '\.store\(|\.rcu\(|\.swap\(' crates/`
   → for each hit, resolve the receiver's type at its declaration.
   Atomic-ordering false positives (`AtomicUsize` etc., e.g.
   `tests/engine.rs:52`) are excluded **by type verification**, never
   by pattern alone.
3. **Classification rubric** (record every hit in the report's table;
   the table is the evidence):
   - (a) production code in `taskboard-state` → compliant (expected:
     `actor.rs:258` `from_pointee` boot swap, `actor.rs:487` `publish`);
   - (b) production code anywhere else → **finding** (severity:
     writing live engine state = P0-class risk; judge by what it
     writes);
   - (c) test code constructing/writing **its own fixture** ArcSwap
     (never the engine's instance) → recorded fact, acceptable by
     design (orientation: `ui-slint/tests/golden_visuals.rs:94`,
     `journeys.rs:44`, `support/driver.rs:261`, `support/fake_engine.rs:140`);
   - (d) test code writing **the engine's live instance** obtained via
     `shared_state()` → determinism/hygiene finding (C axis);
     orientation suspects to verify: `ui-slint/src/lib.rs:618,766`
     (`handle.state.store(...)` — planning-time reading suggests
     `#[cfg(test)]` helper modules; **verify the cfg gate and whose
     instance the handle owns** before classifying).
4. **Design-observation pass** (record as facts, likely P3 / cross-ref
   to chunk 16): `EngineHandle::shared_state` (actor.rs:196-200) hands
   out `Arc<ArcSwap<AppState>>`, whose type permits `.store` to any
   holder — read-only-ness of the UI side is enforced by convention +
   review, not by type. Note the fact; boundary-enforcement
   *proposals* are chunk 7's axis-O scope (cross-ref, don't design
   here).
