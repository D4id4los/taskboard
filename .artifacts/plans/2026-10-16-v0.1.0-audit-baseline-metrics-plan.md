### 2.2 `§cov` — llvm-cov per crate (decision §D1)

One workspace-wide instrumented run — mirroring the CI coverage lane
exactly (same pinned tools, `--all-features`, nextest, quarantine
script) — then per-crate attribution by aggregating the LCOV file by
path prefix. Per-crate `-p` runs are rejected (§D1): they undercount,
because other crates' integration/E2E tests exercise the audited crate.

```
mkdir -p /tmp/taskboard-audit-phase0
SQLX_OFFLINE=true cargo llvm-cov nextest --all-features --workspace \
    --no-tests=warn --no-report
scripts/coverage-quarantine-profraw.sh target/llvm-cov-target
SQLX_OFFLINE=true cargo llvm-cov report --lcov \
    --output-path /tmp/taskboard-audit-phase0/lcov.info
```

Per-crate aggregation (line coverage primary, branch secondary) from the
LCOV file — SF/LF/LH summed per `crates/<crate>/` prefix:

```
awk -F: '/^SF:/ { c=$2; sub(/^.*crates\//,"",c); sub(/\/.*$/,"",c); k=c }
         /^LF:/ { lf[k]+=$2 }  /^LH:/ { lh[k]+=$2 }
         /^BRF:/ { brf[k]+=$2 } /^BRH:/ { brh[k]+=$2 }
         END { for (k in lf)
           printf "%s\tlines %d/%d (%.1f%%)\tbranches %d/%d\n",
             k, lh[k], lf[k], 100*lh[k]/lf[k],
             (k in brh ? brh[k] : 0), (k in brf ? brf[k] : 0) }' \
  /tmp/taskboard-audit-phase0/lcov.info | sort
```

(The awk shape is committed here; stage 2 verifies it against the actual
LCOV on one crate before trusting the table.) Report table: per crate —
lines covered/total, branch covered/total; one workspace rollup row;
retry log if §D14 fired. **Percentages are measured facts only** — the
report sets no coverage targets and must contain no "should be ≥ X%"
phrasing (origin §5).

is a stage-2 judgment call **within the same box budget**, not extra).

`test_event` with `jq 'select(.type=="test_event") | select(has("execution_time"))'`;

jq -r 'select(.type=="test_event" and has("execution_time"))

## 3. Budget-envelope derivation (axis J, fixed rows)

Every row cites origin §1 devices: Samsung NP-NF310 (Atom N550,
2c/4t in-order @ 1.5 GHz, 1 GB RAM, 1366×768 — the interactive kiosk)
and Acer Aspire One D250 (Atom N270, 1c/2t, 1 GB, 1024×600 — the wall
display). **No GPU-dependent budgets** — gen3 Intel graphics have no
hardware GL on modern Mesa; the kiosk rendering path is Slint's
software renderer (origin §1). All numbers are **analytic targets for
the device class**, labeled as such; on-device validation happens in
the kiosk bring-up spike (backlog), not here. Numbers are fixed in the
report **with the derivation arithmetic shown**, from these rules:

| # | Budget | Analytic target | Derivation basis |
|---|---|---|---|
| 1 | App RSS ceiling | ≤ 200 MB | Origin §2 J figure; leaves OS + software-renderer headroom on the 1 GB boxes (origin §1). |
| 2 | Idle CPU between events | ≈ 0 % | Event-driven architecture (origin §2 J); wake-on-event, no polling loops. Verification method deferred to the kiosk spike. |
| 3 | Full-frame repaint @ 1366×768, software renderer, 1.5 GHz in-order core | ≤ 50 ms full frame; ≤ 20 ms typical partial redraw | Frame buffer ≈ 4.2 MB (1366×768×4 B); single-channel DDR3 bandwidth derated for in-order core + swrast read-modify-write; kiosk UI is event-driven (no animation frame-rate requirement), so latency-to-visible-update, not fps, is the budgeted quantity. Arithmetic shown in-report. |
| 4 | Daemon cold start → first useful frame | ≤ 5 s | Kiosk autostart UX tolerance on a cold, slow-storage netbook; storage `load()` scaling evidence exists in the Criterion hot-path bench (chunk 13 maps it). |
| 5 | Sync-cycle wall time; poll-idle cost | full cycle ≤ 30 s for a typical board; poll-idle CPU ≈ 0 | Cycle bound from device-class network + N550 CPU budget for DTO mapping; idle cost ≈ 0 because polls must be timer-driven. |
| 6 | Binary size | ceiling fixed at ≤ 2× the measured v0.1.0 release asset size (rounded up to a round number), reported alongside the measured sizes | Disk-tight 1 GB netbooks; measured via `gh release view v0.1.0` (§2.10). |

The table contains **no coverage/mutants percentage rows and no
process-quality targets** — origin §5's no-percentage-target rule; the

## 5. Honest-capture rules (binding for stage 2)

1. **Staleness is recorded, never hidden**: the weekly mutants artifact
   predates the tag → run date + head SHA + drift stat in `§mutants`;
   Sonar analysis date + SHA check in `§sonar`.
2. **Partial coverage is a result**: a time-boxed one-off reports
   generated/tested/caught/survived/missed — an expired box with honest
   numbers beats an unreported metric.
3. **SHA mismatches are called out**: any artifact whose analyzed SHA ≠
   `925f50e…` carries a drift line (`git diff --stat <sha> v0.1.0`).
4. **Retries are logged**: known-flaky lanes (llvm-cov watchlist:
   actor_wiremock under instrumentation, profraw corruption — origin
   §1) get up to 2 retries (§D14); each retry is recorded in the
   section, and a persistent failure is reported with whatever the
   surviving profraws support, plus the caveat.
5. **Machine facts are labeled**: all timings/measurements carry the
   §env machine context; nothing is presented as a device-class result.
6. **Percentages are data, never goals** (origin §5): no target,
   ceiling, or "should" phrasing on coverage/mutants numbers anywhere
   in the report.

## 6. Decisions (open questions resolved)

- **D1 — per-crate coverage method**: single workspace-wide
  instrumented run + LCOV per-crate aggregation (path-prefix sum).
  Rejected: six per-crate `-p` runs — they undercount because other
  crates' integration/E2E tests exercise the audited crate; attribution
  by file path with the full test corpus is the honest per-crate number.
- **D2 — nextest version**: align to the CI pin
  (`cargo install --locked cargo-nextest --version 0.9.148`) so §cov
  and §timing match the CI lanes the pins were deliberately set for
  (ci.yml:224-229 comment). Fallback if install fails: run 0.9.146 and
  record the version + mismatch in `§env`.
- **D3 — timed lane**: default feature resolution mirroring the CI
  `test` job (not `--all-features`) — that is the suite CI and users
  run; doc-tests timed separately and never folded in.
- **D4 — slowest-20 extraction**: `--message-format json-experimental`
  + jq over `test_event.execution_time`, with an explicit
  schema-discovery step (the format is experimental; adaptations
  recorded). Sanity check: Σ durations ≤ wall time.
- **D5 — mutants time-boxing**: cargo-mutants 27.1.0 has no
  `--max-runtime` → external `timeout --signal=INT --kill-after=90s`
  wrapper (SIGINT = Ctrl-C semantics the tool handles gracefully);
  boxes: storage 60 min, sync 120 min, weekly-fallback local rerun
  120 min. Output dirs under `/tmp` via `-d` (never `mutants-out/` in
  the repo). After every `--in-place` run: `git status --short` must be
  clean.
- **D6 — weekly artifact**: latest scheduled/dispatched run's artifact
  by exact name `mutation-testing-report-<run_id>`; head SHA vs tag
  drift quantified; known candidate 38244799170 (2026-10-12) re-listed
  at execution.
- **D7 — Sonar route**: sonarqube MCP tools (verified in-session)
  primary; web-UI transcription fallback; unavailable → honest P3. The
  tag == main HEAD at planning time, so an exact SHA match is plausible
  — but it is verified from CI run history, never assumed.
- **D8 — pedantic clippy**: dispatch command verbatim +
  `--message-format short` for per-crate counting; default features;
  report-only.
- **D9 — machete**: `cargo install --locked cargo-machete` at stage-2
  start (not installed at planning); version into `§env`; every flag
  triaged (true-unused / macro-only FP), none acted on.
- **D10 — churn**: commit count per path (`git log --name-only -M`),
  top 30 + per-crate rollup; renames credit the new path; method noted
  in the section.
- **D11 — budget numbers**: fixed in-report with arithmetic shown, all
  labeled device-class-analytic; dev-machine reference captures
  optional and explicitly labeled as such; binary sizes measured from
  the actual `gh release view v0.1.0` assets.
- **D12 — anchor order**: `§env` first, then §2.2's metric order;
  conv 6 fixes the anchor *names*, this fixes the layout order.
- **D13 — scratch discipline**: everything under
  `/tmp/taskboard-audit-phase0/`; the repo diff stays exactly plan +
  report (conv 8).
- **D14 — flaky retry policy**: up to 2 retries on the known-flaky
  lanes, every retry logged in the section; the CI quarantine script
  is reused verbatim before any `llvm-cov report`.

## 8. Risks & fallbacks

1. **Mutants box expires early into the sync crate** (12k lines vs a
   2h29m CI sweep of domain+state): partial results are the expected,
   honest outcome; scoped re-run only within the same box budget.
2. **llvm-cov flakiness** (watchlist: actor_wiremock, profraw
   corruption): quarantine script + §D14 retries; worst case the crate
   row carries a caveat instead of a number.
3. **nextest JSON schema drift** (experimental flag): schema-discovery
   step + adaptation recorded; the wall-time number never depends on it.

## 9. Gates, diff shape, non-goals

- **Diff shape (conv 8)**: exactly two files — this plan and the
  report. No backlog edits (conv 7), no production changes (origin
  §5 read-only discipline), no lint/CI/Cargo.toml touch-ups.
- **Gates (§1.4)**: pre-commit fmt/clippy hooks fire on commit
  (markdown-only diff); CI runs the full suite on the PR — the tree is
  the shipped-green tag plus two artefact files, so a red check is an
  environment finding diagnosed on the branch, never a production
  edit. Stage 3 ships (push + PR + `gh pr checks --watch`).
- **Non-goals** (dispatch §2): findings beyond metric anomalies
  (anomalies themselves are P3 observations in conv-4 format);
  percentage targets of any kind; fixes; CI changes; re-benching the
  Criterion hot path (chunk 13); mutants triage (chunk 14); the
  Bencher graduation decision (chunk 13).
