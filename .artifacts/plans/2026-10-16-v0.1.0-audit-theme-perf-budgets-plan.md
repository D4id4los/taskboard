### 3.2 Gap sketches (S1–S6) — what a remediation agent would add

Every sketch states: **path measured (file:line), metric, pass
criterion expressed against the §budgets value (never a percentage),
fixture source, harness kind, device-relation caveat (D2)**. Sketches
are designs, not code — authoring benches is remediation (chunk
non-goal).

- **S1 — RSS smoke harness (row 1)**: not a Criterion bench — a script
  that launches the real daemon headless (software renderer path) with
  the N = 10 000 fixture database, soaks until steady state, and reads
  `VmRSS` from `/proc/<pid>/status`. Pass: ≤ 200 MB *on the kiosk
  device*; dev-machine run is a smoke reference only (D2/D3). Includes
  a static composition estimate as the analytic cross-check (sqlite
  cache defaults, renderer buffers) — the estimate is derived from
  code, labeled analytic.
- **S2 — UI refresh+repaint bench (row 3 + input→visible)**: extend the
  `test_platform.rs` seam from "renderer constructible, never draws" to
  draw-into-buffer: one Criterion bench measuring (a) the pure refresh
  pass (signal drain + `presentation` + `models.rs` rebuild) at N tasks
  and (b) one full-frame software-render into a 1366×768 buffer plus a
  partial-draw case. Fixture: reuse `benches/support/mod.rs` shapes
  (D8 convention). Pass criterion: full-frame ≤ 50 ms *device-scaled*;
  dev-machine numbers reported with the analytic derate note; absolute
  conformance is kiosk-spike territory. Risk note: if the pinned slint
  version's software renderer cannot render headlessly into a buffer
  from the custom Platform, the sketch records the exact API blocker
  as part of the gap finding (that is evidence, not failure).
- **S3 — cold-start smoke harness (row 4)**: time-to-first-useful-frame
  of the real binary on the N-task fixture DB (spawn → first frame
  event). Criterion is the wrong tool (process spawn, config, painter
  startup); a scripted stopwatch harness is right. Pass: ≤ 5 s on the
  device class; the `load()` leg's scaling already has criterion
  evidence (hot_path `load`).
- **S4 — DTO↔domain mapping bench (row 5 CPU legs)**: Criterion over
  the pure mapping functions (`mapping.rs` deck DTO ↔ domain at board
  scale N) — deterministic fixtures, same conventions as the hot_path
  plan (D3/D8). Answers: how much of the 30 s cycle budget the CPU
  legs consume on-device (analytic derate). Optional phase 2 (recorded,
  remediation may cut it): a wiremock-backed full-cycle wall-time
  harness — explicitly labeled network-dominated, so its regression
  value is in the CPU share, not the wall time.
- **S5 — binary-size tracking step (row 6)**: a CI step reporting
  `target/release/taskboard` size per build (and optionally
  cargo-bloat top-N), alerting at 2× the v0.1.0 reference. Depends on
  F1-01 (release assets) for the *true* baseline; until then the
  dev-machine reference + ratio rule from §budgets stands.
- **S6 — engine-transition bench (input→visible chain)**: Criterion
  over one engine message end-to-end on the pure path — `plan_command`
  → apply against a **fake repository** (AGENTS §5 fakes-over-mocks; a
  HashMap-backed `TaskRepository`) → interpret → `ArcSwap` publish +
  broadcast — at N ∈ {100, 1k, 10k} with the shared fixture builder.
  Isolates the engine leg from sqlite (whose leg hot_path already
  owns). Pass criterion: contributes negligibly against the row-3
  composed budget; exact per-leg allowance derived in remediation
  once S2/S6 numbers exist (this chunk invents no new budget values —
  the envelope is frozen).

### 3.5 Bencher graduation evaluation (recommendation; decision lands in the user session)

Shape: (1) **wiring facts at the tag** — ci.yml:279–315 (adapter,

artifact-based tracking. The final graduation decision is the user's
(chunk 17 session, audit plan §2 J); this chunk delivers the
decision-grade recommendation only. No CI edit (origin §6 — Bencher
stays backlog unless promoted).

## 5. Decisions (open questions resolved at planning time)

- **D1 — run the existing bench?** Yes, one run, 30-min hard box
  (§3.3). The prompt allows it; per-op numbers materially improve the
  row-4 mapping; §timing's lane durations are a weaker substitute that
  stays as fallback.
- **D2 — dev-machine vs device budgets.** All in-repo instruments run
  on the dev machine; budgets target 1.5 GHz in-order cores. Every
  number carries an analytic derate note; no fabricated conversion
  factor; absolute conformance statements are reserved for the kiosk
  spike (audit plan §1/§2 J). This mirrors §budgets' own "analytic
  targets" framing.
- **D3 — rows 1/2 are not benchable in-process.** RSS and idle CPU get
  *smoke-harness* sketches (S1, S3) and an *analytic* census (C1),
  not Criterion benches — a bench measuring its own process RSS or
  CPU-idle-ness answers nothing. Recorded so stage 2 doesn't force a
  criterion shape onto them.
- **D4 — no new budget numbers.** The envelope is frozen from §budgets;
  per-leg allowances (e.g. engine vs draw share of row 3) are derived
  in remediation once S2/S6 measurements exist. This chunk maps and
  sketches; it does not re-derive or extend the envelope (dispatch
  non-goal "budget re-derivation").
- **D5 — F1-04 ownership.** Judged here (bench owner), consumed by
  chunk 14; recommendation + trade-offs only, no CI edit.
- **D6 — Bencher output shape.** One recommendation, options and
  trade-offs named, final decision explicitly reserved for the user
  session (audit plan §2 J; dispatch §14 "the decision lands in the
  user session").
- **D7 — sync row split.** Row 5's cycle wall time is network-dominated
  → in-repo instrument = CPU-leg bench (S4 mapping) + optional wiremock
  harness (labeled network-dominated); poll-idle ≈ 0 folds into the
  C1 census; absolute cycle time is spike material.
- **D8 — fixture reuse.** All task-scale sketches reuse the
  `benches/support/mod.rs` deterministic fixture builder (via `#[path]`
  or a promoted shared module — the remediation agent picks; both
  conventions already exist at the tag) rather than new fixture code.
- **D9 — S2 renderer feasibility is an outcome, not a precondition.**
  If headless draw-into-buffer is not achievable with the pinned slint
  version's API, the blocker itself becomes evidence in the gap
  finding (that is the honest answer to "what would the bench
  measure").
- **D10 — S5 is blocked-aware.** The binary-size tracking sketch
  carries the F1-01 dependency (no release assets exist; §budgets
  D-2's dev-machine reference + ratio rule governs until fixed).
- **D11 — flow-model report is a cross-check, not an input
  requirement.** The C1 census greps the tree directly; chunk 2's
  merged edge table is used only to confirm no actor was missed
  (dispatch §1.2: chunks 10–14 "do not strictly need it but may cite
  it").

## 6. Effort & risks

**Effort**: M (per dispatch table). Stage 2 ≈ ½ day: census greps +
mapping table ≈ 2 h; sketches ≈ 2 h; bench run ≤ 30 min inside its box;
Bencher + F1-04 evaluations ≈ 2 h; report ≈ 1 h.

**Risks**:

1. **Sketches drift into authoring** — the classic scope creep; the
  plan pins sketches to path/metric/pass-criterion prose (dispatch
  non-goal: "authoring new benches is remediation"). Stage 3 checks
  the diff contains no code.
2. **S2 headless-draw API risk** — slint's software renderer may not
  expose a clean render-into-buffer path from a custom Platform at the
  pinned version; handled by D9 (blocker = evidence).
3. **Bench-run overrun** — fresh worktree build + N = 10 000 tier; the
  30-min hard box with honest abandonment (§3.3) bounds it.
4. **Line-number drift** — all file:line cited here were verified at
  the tag at planning time; stage 2 re-verifies before citing (the
  worktree *is* the tag tree, so worktree numbers are tag numbers).
5. **Bencher unknowns** — token-secret existence and Bencher-side
  project state are not readable from the repo; recorded as unknowns
  so the recommendation doesn't silently assume either way.
