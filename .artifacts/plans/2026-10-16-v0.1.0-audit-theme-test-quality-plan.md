## 2. Risk-map construction method (deliverable 1)

**Purpose** (origin §2 B): one table answering "if this behavior broke,
would a test at the right layer catch it?" — per row:

`behavior → crate → risk (what breaks, user-visible consequence) →
required test tier (per testing_strategy §4–§9 + AGENTS §5) → existing
test (file:line @ v0.1.0) or GAP`.

**Construction, three passes:**

1. **Origin-named seed rows** (non-negotiable, origin §2 B lists them):
   conflict policy (R-algebra), outbox crash-safety, reminder firing,
   IPC protocol, config precedence. Stage 2 locates each behavior's
   sites and current tests afresh at the tag — the seed rows get
   first-class rows even if a crate chunk already covered them, because
   the synthesis map must stand alone for the decision session.
2. **Rows imported from the crate chunks** (cited, not re-derived): the
   8 state rows (§5.1 of chunk 4: apply-durability, drain lifecycle,
   reminder at-most-once, `StorageFailed` edge, nudge fan-out, flush
   barrier, memory≡disk P4, ingestion-equality negatives), the 8 app rows
   (chunk 4→8: IPC relay, config precedence + secret-free construction,
   dispatch/exit codes, daemon lock, REPL editing/history, completion
   parity, secrets redaction, attach/detach), domain's 8 behavior
   families (chunk 3 §7.1), storage's risk core (outbox crash-safety +
   decode integrity + migration replay, chunk 5), sync's tier-family
   risk anchors (chunk 6: push correctness, pull dead-board
   determination, poll correctness, decode diagnostics), ui-slint's
   five (chunk 7 §9.2). Import = row + citation of the chunk's verdict;
   re-verification only for rows whose cited test anchors fail
   spot-check (then it is a finding either way).
3. **Additions argued from crate findings** — rows for behaviors a crate
   chunk flagged as under-tested but did not own a map row for, and
   cross-crate behaviors no crate could own. Candidates spotted at
   planning time (stage 2 argues each, keeps or drops with a recorded
   reason): board-side conflict arms (F3-10 — "untested at every tier"
   makes it a top risk-map row), `UpdateTask.archived` arm (F3-11),
   loop-exit/all-sources-closed break (F4-01), negative ingestion
   halves (F4-02), keyring adapter round-trip (gated, CI-unwired),
   `update_task` defer/delta chain (F6-01's 14 survivors), live-tier
   wire drift (the known-server matrix — pinned only by fixtures/contract
   tests, by design).

**Verdict vocabulary** per row: `covered-at-right-tier` / `covered at
wrong tier (finding)` / `gap (finding)` / `accepted-risk (P3, reason)`.
Severity per origin §3. The map's coverage claim is qualitative — **no
percentage targets anywhere** (origin §5; §cov numbers may appear only
inside a row's evidence, never as row pass/fail criteria).

Expected scale (orientation estimate, not a ceiling or floor): ~5 seed +
~30 imported + ~5–8 argued ≈ 40±10 rows.

## 3. Mutants-triage rubric (deliverable 2)

**Population** (all from `§mutants`, conv 6 — no re-runs, decision D3):
24 weekly domain+state survivors + 3 storage + 44 sync = **71 survivors**,
plus 8 weekly + 3 sync **timeouts** (triaged as hang-mode outcomes per
chunk 4 §5.2-3 / chunk 6 F6-09 — efficiency observations, not coverage
gaps, unless the risk map says the hung behavior is itself unpinned).

**Staleness rule** (F1-02 binding): the weekly sweep describes the
2026-10-12 tree (`6a536451`), 4 545 lines before the tag in the swept
crates — the whole reminders feature post-dates it. Every weekly-sweep
verdict carries a per-site staleness bound exactly as chunk 4 §5.2
modeled (site unchanged at tag + observing test set unchanged → verdict
current; else flagged). The one-off storage/sync sweeps ran **on the tag
tree** (baseline §mutants(b)) — no staleness caveat. Reminders and all
of ui-slint/app have **zero mutant evidence**; that absence is itself a
recorded observation (cross-refs: F7-09 for ui-slint, chunk 8's D9 for
app), not something this chunk fixes.

**Rubric** — each survivor (or pre-adjudicated family) maps to exactly
one risk-map row, then:

| Case | Verdict |
|---|---|
| Survivor sits in a high-risk row (seed rows + rows whose breakage is data-loss/correctness class) **and** no crate chunk already adjudicated it | **F14-NN finding** (severity per row's risk; proposed action = the missing differential/negative test, effort guess) |
| Survivor already adjudicated by a crate chunk (F3-08/F3-12, F4-01/F4-02, F5-01/02, F6-01…F6-24) | **cross-ref rollup row** — cite the finding ID(s); chunk 14 adds the synthesis view only (see below) |
| Survivor in a low-risk/trivia position (formatters, `expecting` messages, Debug impls, dead-API helpers like `is_noop`) | **P3 observation**, one lumped row (no per-survivor findings) |
| Equivalent mutant (provably unkillable, e.g. `max_ts` `>`→`>=` on a total order) | **P3**, proposed action = cargo-mutants ignore-pattern so sweeps stop recounting it |

**Synthesis verdicts chunk 14 adds on top of the rollup** (the reason it
exists): (a) an *accounting proof* — every one of the 71 survivors is
triaged exactly once (crate finding, F14 finding, or P3 lump), with the
arithmetic shown; (b) cross-crate *patterns* the per-crate views cannot
see — e.g. "negative halves unpinned" spans state (F4-02) and domain
(F3-08/F3-12); the timeout families cluster where hangs are killed by
the cap, not assertions (F4-07); whether survivor density correlates
with §churn hotspots (app's `commands/mod.rs` has no mutant evidence at
all — is that the next sweep's target?); (c) a recommendation for the
**next sweep's scope** (weekly cadence exists; F7-09 proposed ui-slint;
the question "which crates deserve sweep coverage given the risk map"
gets exactly one recommendation, decision-grade).

## 4. Determinism grep battery (deliverable 3)

One battery, run once over the tag tree (`git grep` at `v0.1.0`,
workspace scope `crates/`), hits classified per the verdict column —
**crate chunks 4–7 already swept their crates clean**; the value here is
the single workspace view (esp. app, whose crate-scoped sweep found the
real-clock debt) and the *adjudication* of known hits:

| # | Pattern family | Grep shape | Hit classification rule |
|---|---|---|---|
| 1 | sleeps | `std::thread::sleep`, `tokio::time::sleep`, `thread::sleep_ms` | violation unless (a) poll-turn inside a deadline-bounded predicate loop (the AGENTS §5-sanctioned shape — chunk 4 §7.1 lists the canonical sites), (b) tier-2/3 real-server harness (wall-clock by nature), or (c) production timer arm (`sleep_until` armed from injected clock — verify the clock seam) |
| 2 | wall-clock in non-seam paths used by tests | `Utc::now\|Local::now\|SystemTime::now` over `src/`+`tests/` | violation when a *test's* outcome depends on wall-clock; justified-with-reason when used as a relative base ±offset (ui-slint §9.3 pattern) or in production display paths (cross-ref chunk 11 — clock-seam inventory is axis L, not C) |
| 3 | unbounded channels | `unbounded_channel`, `std::sync::mpsc` | violation in production paths (AGENTS §3 mandates bounded mpsc/broadcast/oneshot); dev/test-harness use judged by whether it can mask a lost-backpressure bug |
| 4 | network/fs in unit tiers | `TcpStream\|reqwest::\|std::fs::` confined to files the crate tier maps classify as unit tier | violation (tier-0/1 must be hermetic); tempfile use where the property is file-backed is justified (chunk 5's rubric) |

Every hit gets a one-line verdict: `violation → F14 finding` /
`justified (reason + file:line)` / `cross-ref (owner chunk)`. The
battery's output table is complete (every hit listed), so stage 3 can
replay it. **Known adjudications waiting for this pass**: the app
real-clock quiet windows (F8-12: `cli_reminders.rs:542–556` 3 s quiet
window + 10 ms poll; root cause `start_paused` vs sqlx pool-acquire on a

lane question (F1-04, six Criterion-in-bench tests ≈62 s of the default
lane — hygiene half is chunk 14's, bench-coverage half is chunk 13's,
decision D8).

## 10. Risks

- **Anchor drift**: crate-chunk `file:line` cites were verified by
  those chunks against the same tag — but spot-checks can fail; a
  failed spot-check is reported, not silently trusted (§1.3 rule).
- **Scope creep into crate re-audits**: the non-goals line is sharp
  (dispatch §15); the §1.3 table is the guardrail — when a question is
  crate-scoped and adjudicated, cite and move on.
- **The risk map becoming a percentage exercise in disguise**: origin
  §5 forbids it; the verdict vocabulary is qualitative by construction.
- **28-vs-29 reconciliation reads as weakening an acceptance
  criterion**: it is the opposite — the criterion is completeness of
  enumeration (stage 3 counts independently per prompt 14.3).
- **Determinism battery false positives**: the sanctioned-shapes
  catalogue (§4 verdict column) exists precisely so justified hits are
  not findings; every verdict line carries its reason.
