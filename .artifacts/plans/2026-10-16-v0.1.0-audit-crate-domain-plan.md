## 5. Findings format, IDs, and report outline

- Findings: `F3-NN · severity P0–P3 · axis <E|G|F|I.4|H|B|C> ·
  evidence (file:line @ v0.1.0 | baseline §anchor) · proposed action ·
  effort S/M/L` (conv 4; origin §3). Severity calibration: P0 in a
  pure crate is plausible only for correctness in sync/reminders
  logic (origin §3) — e.g. a mis-derived pending-intent that can
  drop or resurrect user data. A finding without action+severity is
  an observation → P3 (origin §5).
- Report skeleton (house `[Report]` style): header (date, branch,
  plan link, status) → method & inputs (anchors cited; verbatim
  commands for any read-only run) → §E → §G → §F → §I.4 → §H → §B/C →
  cross-refs (§4 table instantiated) → findings index → axis coverage
  table (conv 5; rows E, G, F, I.4, H, B, C — each "N findings /
  clean / accepted-risk", no silent skips) → deviations from this
  plan, if any.
- Repo hygiene: scratch output (e.g. D4's LCOV) stays in `/tmp`;
  the report carries excerpts/tables only; diff = plan + report
  (conv 8).
