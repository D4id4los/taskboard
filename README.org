=taskboard= is a cross-platform task management and reminder application
designed for both low-power, ambient display *Kiosks* and interactive
*Desktop* workstations. Built in Rust, it features an asynchronous,
event-driven multi-actor core with an offline-first architecture powered by
Nextcloud API synchronization and local SQLite caching.

* Key Features

- *Dual-Mode Operation:* Runs seamlessly as a passive, low-power Kiosk
  display or an interactive Desktop manager.
- *Headless Core Architecture:* Decoupled presentation layer enabling
  non-blocking UI rendering and interchangeable front-end drivers (Slint,
  iced, egui).
- *Offline-First Synchronization:* Local SQLite caching ensures continuous
  operation during network drops, background-syncing with Nextcloud when
  reconnected.
- *Lock-Free State Reads:* Zero-contention UI frame rendering powered by
  atomic state pointer swaps (=arc-swap=).

* Download

Pre-built binaries for the first-class platforms (x86_64 Linux & Windows)
are attached to every [[https://github.com/D4id4los/taskboard/releases][GitHub Release]]. Each release ships a
=taskboard-<version>-<target-triple>.tar.gz= (Linux) or =.zip= (Windows)
containing the =taskboard= binary, both licenses, the README, and the
changelog, plus a matching =.sha256= checksum file and a combined
=SHA256SUMS=.

To test release packaging locally (byte-identical to a CI leg):

#+begin_src sh
python3 scripts/package_release.py          # build + archive into target/dist/
python3 scripts/package_release.py --check  # verify an existing archive
#+end_src

Until the first release is cut, build from source:

#+begin_src sh
cargo build --release -p taskboard-app
#+end_src

* Architecture Overview

The application employs a /Headless Core with an Event-Driven Multi-Actor
Architecture/ built on Tokio. User interactions or visual timers never
mutate state in place: components publish intents over async channels, a
central State Engine processes them, and immutable snapshots are consumed
by the UI. Full details, including the channel topology and crate
dependency rules, live in [[./docs/architecture.org][docs/architecture.org]].

* Dev Quickstart

** Prerequisites

- *Rust Toolchain:* =stable=, managed via [[https://rustup.rs][rustup]] (the pinned
  =rust-toolchain.toml= is picked up automatically). Edition 2024, MSRV 1.96.
- *System Dependencies:* =gcc= or =clang= (for SQLite linking). Graphics
  backend drivers (OpenGL/Vulkan) will be required for the Slint UI once it
  lands.
- *Recommended tooling:* =cargo-nextest=, =cargo-deny=, =cargo-llvm-cov=
  (all used by CI; install with =cargo install cargo-nextest cargo-deny
  cargo-llvm-cov=).

** 1. Enable the Git Hooks

The repository ships a =pre-commit= hook (fmt + clippy). Point git at it:

#+begin_src sh
git config core.hooksPath .githooks
#+end_src

** 2. Build the Workspace

#+begin_src sh
cargo build --workspace
#+end_src

** 3. Run the Application

#+begin_src sh
cargo run -p taskboard-app
#+end_src

Release artifacts can be built and verified locally with
=python3 scripts/package_release.py= (see [[Download][Download]]).

** Configuration

=taskboard= uses hierarchical configuration loading via =figment=. Settings
merge from embedded defaults, a =taskboard.toml= file in the working
directory (or =--config <path>= / =TASKBOARD_CONFIG=), and =TASKBOARD_=
prefixed environment variables (highest priority; =__= nests, e.g.
=TASKBOARD_SYNC__POLL_INTERVAL_SECS=).

Config files carry *no secrets* — unknown keys inside a table are a
hard error, so an =app_password= line cannot even decode. The Nextcloud
app password is resolved through the OS keyring (default) or, on
headless machines, the =TASKBOARD_APP_PASSWORD= environment variable
(set =[nextcloud] credential_store = "env"= explicitly; there is no
silent fallback).

Example =taskboard.toml=:

#+begin_src toml
[nextcloud]
server_url = "https://cloud.example.com"
username = "your-login"

[sync]
poll_interval_secs = 30
#+end_src

** Running the Daemon (M1 quickstart)

1. Configure =taskboard.toml= as above.
2. Provide the app password, either in your desktop keyring

   #+begin_src sh
   # paste the app password when prompted; the entry name is
   # username@host-of-server (what KeyringStore looks up)
   printf 'your-app-password' | secret-tool store --label=taskboard \
     service taskboard username your-login@cloud.example.com

   # verify / clean up later:
   secret-tool lookup service taskboard username your-login@cloud.example.com
   #+end_src

   or via the environment escape hatch:
   =TASKBOARD_APP_PASSWORD=...= plus =credential_store = "env"=.
3. Run the headless sync daemon:

   #+begin_src sh
   cargo run -p taskboard-app -- daemon
   #+end_src

It pulls the bound board, pushes local edits, retries offline, and
shuts down gracefully on Ctrl-C/SIGTERM (flushing every accepted
command and the sync actor's final report first).
