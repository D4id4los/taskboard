#+title: taskboard
#+options: toc:nil

[[https://github.com/D4id4los/taskboard/actions/workflows/ci.yml/badge.svg]]

=taskboard= is a cross-platform task management and reminder application
designed for both low-power, ambient display *Kiosks* and interactive
*Desktop* workstations. Built in Rust, it features an asynchronous,
event-driven multi-actor core with a *stand-alone-first* architecture:
local task management works with no server at all, and Nextcloud Deck
synchronization is an optional connector (ADR 0010).

* Key Features

- *Dual-Mode Operation:* Runs seamlessly as a passive, low-power Kiosk
  display or an interactive Desktop manager.
- *Headless Core Architecture:* Decoupled presentation layer enabling
  non-blocking UI rendering and interchangeable front-end drivers (Slint,
  iced, egui).
- *Stand-alone First:* Work fully offline with zero network and zero
  credentials; local SQLite is the source of truth (durable from the
  reply, no keyring needed).
- *Optional Nextcloud Sync:* When (and only when) a server is
  configured, background-syncing with Nextcloud Deck drains the local
  write-ahead queue and pulls remote content.
- *Lock-Free State Reads:* Zero-contention UI frame rendering powered by
  atomic state pointer swaps (=arc-swap=).

* Architecture Overview

The application employs a /Headless Core with an Event-Driven Multi-Actor
Architecture/ built on Tokio. User interactions or visual timers never
mutate state in place: components publish intents over async channels, a
central State Engine processes them, and immutable snapshots are consumed
by the UI. Full details, including the channel topology and crate
dependency rules, live in [[./docs/architecture.org][docs/architecture.org]].

** Configuration

=taskboard= uses hierarchical configuration loading via =figment=. Settings
merge from embedded defaults, a =taskboard.toml= file in the working
directory (or =--config <path>= / =TASKBOARD_CONFIG=), and =TASKBOARD_=
prefixed environment variables (highest priority; =__= nests, e.g.
=TASKBOARD_SYNC__POLL_INTERVAL_SECS=).

Config files carry *no secrets* — unknown keys inside a table are a
hard error, so an =app_password= line cannot even decode. The Nextcloud
app password is resolved through one of three explicitly selected
stores (there is no silent fallback):

- =keyring= (default) — the OS keyring;
- =env= — the =TASKBOARD_APP_PASSWORD= escape hatch for headless
  machines and CI;
- =file= — the encrypted-file store for kiosk appliances without a
  Secret Service: a machine-generated =0600= key file beside the
  database plus ChaCha20-Poly1305-encrypted envelopes under
  =<db-dir>/credentials/= (see ADR 0008). It protects against other
  local users and world-readable copies — not against root or
  full-disk theft; weaker than the keyring where the keyring exists.

Replace every =<placeholder>= below with your own values.

Example =taskboard.toml= (a *Nextcloud* setup — a fresh install needs
no config at all):

#+begin_src toml
[nextcloud]
server_url = "https://<your-nextcloud-host>"   # e.g. https://cloud.example.com
username = "<your-nextcloud-username>"

[sync]
backend = "nextcloud"   # optional; absent = auto: nextcloud iff server_url is set
poll_interval_secs = 30

[ui]
scale = 1.0             # theme token multiplier; 0.5–3.0 enforced at load

[preferences]
day_start_time = "00:00"  # when "today" begins (device-local, never synced)

[reminders]
sink = "auto"           # auto (default) | log | desktop
#+end_src

=[preferences] day_start_time= accepts =HH:MM[:SS]= and sets the
wall-clock time at which "today" begins (drives the today view's
sections); an unparseable value is a typed
=invalid-day-start-time= configuration error, never a silent
default. =[reminders] sink= picks the reminder delivery path:
=auto= (the default) means the desktop mode gets toast
notifications and daemon/kiosk keep the journald log path;
=log= and =desktop= force either one explicitly.

*Multiple connectors* (optional): the scalar shape above is the legacy
form and still loads unchanged — a resolved =nextcloud= backend
synthesizes exactly one connector named =nextcloud=. For two or more
servers, declare a =[[sync.connectors]]= array of named entries
instead (=name= is kebab-case and unique — it is the connector id
everywhere; the first entry is the default connector):

#+begin_src toml
[[sync.connectors]]
name = "alpha"
backend = "nextcloud"
server_url = "https://cloud-a.example.com"
username = "<user-a>"

[[sync.connectors]]
name = "beta"
backend = "nextcloud"
server_url = "https://cloud-b.example.com"
username = "<user-b>"
#+end_src

The two representations never mix silently — every mix is a typed
config rejection naming the offending key: a scalar =[sync] backend=
plus the array (=connector-shape-mixed=), a =[nextcloud]= table plus
the array (=nextcloud-table-with-connectors=), =standalone= with the
array, a duplicate or non-kebab-case =name=
(=duplicate-connector-name= / =invalid-connector-name=), or a
resolved =nextcloud= backend with an empty array
(=invalid-connector-entry=). A resolved =standalone= backend means no
connectors at all. Note that the array cannot be expressed through
environment variables, and setting =TASKBOARD_SYNC__BACKEND= over an
array config is now a loud error.

** Display scaling

The desktop UI scales on two orthogonal axes (they compose; both need a
restart to apply):

- =[ui] scale= (config): multiplies every theme dimension — spacing,
  radii, text roles, the window's default size. Values outside the
  =0.5=–=3.0= range are a typed configuration error, never silently
  clamped.
- =SLINT_SCALE_FACTOR= (environment): the window-manager-level DPI
  override honoured by the Slint winit backend at window creation. Use
  it when the OS reports the wrong DPI for your display; it is read
  before the UI starts and never set by the app itself.

** Quickstart: stand-alone first

No server, no keyring, no network — create a board and work:

#+begin_src sh
taskboard boards create "Personal"
taskboard stacks add "Todo"
taskboard tasks add "first task"
taskboard tasks list           # shows board/stack/task + the stand-alone note
#+end_src

Changes are durable locally the moment the command replies; the
=sync: idle (N pending)= footer counts the local write-ahead queue
nothing drains until a connector attaches.

*Editing* the board needs no server either:

#+begin_src sh
taskboard tasks edit "first task" --due 2026-10-20 --json
taskboard labels add urgent
taskboard tasks label "first task" urgent
taskboard stacks rename Todo Backlog
taskboard stacks move Backlog --order 2
taskboard boards rename "Personal Work"
taskboard tasks delete "first task"      # no confirmation; repeats are idempotent
#+end_src

Selectors are uuids, unique 8+-character uuid prefixes, or exact
titles; destructive verbs cascade what the server would cascade
(=stacks delete= takes its tasks with it). =labels list= shows
assignment counts, and =config print= dumps the effective
(secret-free) configuration with its validity diagnosis.

Due dates are UTC-only: a bare =YYYY-MM-DD= (=--due 2026-10-20=)
means midnight UTC; an RFC-3339 timestamp with an explicit offset is
accepted and normalized to UTC (=2026-10-24T09:00:00+02:00= is stored
as 07:00 UTC); a timestamp without an offset is refused. Storage and
all display — lists, the day banner, and the overdue/due-soon
colouring — are UTC.

** Daily driving: fields, capture, timers, find

Beyond deadlines, tasks carry *planning fields*: =--scheduled= (when
you intend to begin; the =--due= vocabulary), =--effort= (bare digits
= minutes; =s=/=m=/=h= compose), and =--importance=/=--urgency=
(=very-low=…=very-high=); =none= clears a field:

#+begin_src sh
taskboard tasks edit "first task" --scheduled 2026-10-26 --effort 1h30m --importance high --urgency low
#+end_src

=--scheduled= accepts RFC-3339 or =YYYY-MM-DD= (the =--due=
vocabulary), =--effort= composes =s=/=m=/=h= (bare digits = minutes),
and the two priority fields take =very-low=…=very-high=.

Quick capture files a thought without aiming it first:

#+begin_src sh
taskboard capture "idea: watering rota"          # → the global Inbox
taskboard capture "mow the lawn" --board Personal  # → that board's Backlog
#+end_src

With no =--board=, a single live board's Backlog receives the task
(created on demand); the global Inbox is a real board created unbound
on first capture. In the desktop window, Ctrl+K opens the capture
overlay (Enter commits-and-continues into the Inbox, Esc closes).

Standalone timers are one-shot, host-local alarms — never synced, no
UI surface:

#+begin_src sh
taskboard timers add --in 25m "pomodoro"
taskboard timers add --at 17:30 "leave pickup"
taskboard timers list
taskboard timers cancel pomodoro
#+end_src

And =find= searches everything at once — boards, stacks, and tasks,
best match first (exit 0 with an empty table when nothing matches):

#+begin_src sh
taskboard find water                # everything mentioning "water"
taskboard find lawn --type task --limit 5
#+end_src

In the desktop window, the search palette (Ctrl+F / Ctrl+s or =/=)
jumps straight to a board, stack, or task.
** Launching taskboard

What a bare =taskboard= invocation runs depends on the =[app] mode=
setting (default =daemon=), whether stdin is a terminal (TTY), and
whether a display is available; an explicit verb (=gui=, =daemon=)
bypasses the resolution. The shipped routing, one row per case:

| invocation                             | TTY | display | lifecycle                         |
|----------------------------------------+-----+---------+-----------------------------------|
| bare =kiosk= mode                      | any | any     | the fullscreen appliance (ADR 0016) |
| bare =desktop= mode                    | any | any     | desktop GUI                       |
| bare =daemon= mode, TTY                | ✓   | any     | interactive REPL (ADR 0011)       |
| bare =daemon= mode, no TTY, display    | —   | ✓       | desktop GUI (#236)                |
| bare =daemon= mode, no TTY, no display | —   | —       | headless daemon lifecycle         |
| explicit =taskboard daemon=            | any | any     | headless daemon lifecycle, always |
| explicit =taskboard gui=               | any | any     | desktop GUI (ADR 0009 amendment)  |

The kiosk row is TTY-independent by design: the display gate lives
inside the appliance lifecycle, so with no display the same
invocation falls back loudly to headless serving over IPC (ADR 0016).

The mode resolution is overridable without a verb:
=TASKBOARD_APP__MODE=desktop taskboard …= forces the mode for one
invocation (figment's =__= nesting), or set =[app] mode =
"desktop"= in =taskboard.toml=; the same environment form takes any
mode value.

Release archives ship a =taskboard.desktop= launcher (the repo copy
lives in =contrib/=): put the =taskboard= binary on =PATH= (e.g.
=~/.local/bin=) and copy the file to
=~/.local/share/applications/=, or mark it executable and trusted in
the file manager and double-click it straight from the extracted
archive. Its =Exec= is =taskboard gui= — the double-click path is
the =gui= verb row above.

In the desktop window, a board-switcher strip sits above the kanban
(one segment per live board; the compact layout hides it — keyboard
switching still works). =b= / =B= walk =board.next= / =board.previous=
in every keymap preset's board scope (no wrap at the ends), and each
board's sync badge follows the selected board. Switching is pure view
state — nothing is dispatched to the engine.

The desktop window launches on the *Today* view — a cross-board
surface with overdue / scheduled / due-today / done-today sections
(it is subjectless: every live board at once; kiosk keeps launching
on the board view). Ctrl+K opens quick capture (Enter
commits-and-continues into the global Inbox, Esc closes); the search
palette (Ctrl+F / Ctrl+s or =/=) jumps to boards, stacks, and tasks;
the toolbar's inbox chip routes to the Inbox. The move ring (the
task-move key's stack cycle) *crosses board edges* — it cycles every
live board's stacks uniformly, with =board › stack= hints naming the
landing spot; =tasks move --board <board>= pre-filters the cycle to
one board when that is not wanted.

** Interactive shell (no arguments on a terminal)

Bare =taskboard= with a terminal on stdin opens a =parted=-style REPL
over *one* booted core (ADR 0011) — no bootstrap per command:

#+begin_src sh
taskboard
# taskboard 0.1.0 — interactive session (backend: standalone)
# taskboard> boards create "Personal"
# taskboard> stacks add "Todo"
# taskboard> tasks add "first task" --json
# taskboard> exit
#+end_src

Line grammar: every line is one CLI invocation (quoting with
=shell-words=, a line's =--json= wins for that line only);
=exit=/=quit=/Ctrl-D leave (graceful shutdown, exit 0); Ctrl-C at the
prompt cancels the line; an empty line re-prompts. Mutations are
durable the moment the line replies; the outbox drains on the sync
actor's cadence or a =sync= line. Refused in-session: =daemon=,
=gui=, =login=, =logout=, =config=, and per-line =--config= (the session's
config, connector, and credential store are fixed for the lock
epoch). Tab completion is on: verbs, subverbs, long flags, and the
live stack/task/label titles complete at the cursor (the offered
titles are exactly what the corresponding selector would accept; the
in-session-refused verbs and =--config= are never offered). Submitted
lines persist across sessions in =<data-dir>/taskboard/history=
(owner-only 0600, best-effort: a missing or corrupt file is warned
about and rebuilt, never fatal; prompted secrets are never recorded).
When two live entities share a title, the menu offers one
uuid-disambiguated row per entity — displayed as =title - uuid=,
inserting the full uuid (the one always-exact selector); unambiguous
titles keep the plain row.
The instance-lock mutex applies both ways — a running daemon
makes bare =taskboard= (a *second* core boot) fail with
=instance-locked=: stop the daemon first. Core *verbs* typed while a
daemon runs do not contend — they route over the daemon's socket (see
[[*The daemon and IPC][The daemon and IPC]]). Without a TTY (systemd
units, pipes) the bare-invocation routing of
[[*Launching taskboard][Launching taskboard]] applies unchanged.

** Attaching a server (optional)

#+begin_src sh
cargo run -p taskboard-app -- login   # prompts for server, user, app password
taskboard boards publish              # migrate: local board → new Deck board
# or, onto an existing board (union semantics — see ADR 0010):
taskboard boards list
taskboard boards select <id> --bind-local-board
taskboard sync
taskboard daemon                      # headless sync loop until Ctrl-C/SIGTERM
#+end_src

Once a board syncs app-only data (an effort/importance/urgency edit
or a reminder rule), taskboard creates one card titled
=[taskboard] app-data= in that Deck board carrying a
=taskboard-appdata.json= attachment. That card is taskboard's
document store for the board — *it is not a task; leave it alone*.
The CLI refuses renaming or deleting its local mirror
(=anchor-task-reserved=); deleting it Deck-side triggers a rebuild
from local state on the next cycle, not data loss. The card is
hidden from taskboard's list surfaces and search results.

The =scheduled= field is two-lane: on servers whose Deck version
supports the native start-date field (Deck ≥ 1.19) it rides that
card slot; everywhere else (e.g. Deck 1.17.5) it rides the app-data
document — detected automatically per server, no configuration.

** Multiple boards and connectors

Boards bind independently — there is no one-board invariant. Every
board-scoped verb takes =--board <uuid>=; omitting it resolves the
single live board, and with zero or several live boards the verb
refuses with the typed =ambiguous-board= error (candidates listed).
The connector-targeting verbs (=boards list=, =boards select=,
=boards publish=, =sync=) take =--connector <name>=; an unknown name
refuses with typed =unknown-connector=. =taskboard status= reports
the per-connector =connectors= array (name, derived health, bound
boards) and the flat per-board =boards= array beside the unchanged
aggregate =sync= field.

In the REPL, =boards use <uuid>= sets the session's board selection —
later board-scoped lines pre-fill =--board= from it (query with a
bare =boards use=; one-shot and daemon-socket invocations refuse, it
is session-only).

*Moving a board between connectors* (unbind → reconcile → re-bind on
the other server):

#+begin_src sh
taskboard boards unbind --board <uuid> --confirm      # content and ops stay; ops strand until a re-bind
taskboard boards select <remote-id> --local-board <uuid> --connector beta
taskboard boards reconcile --board <uuid> --confirm   # merge same-title duplicates the pull adopted
#+end_src

Rebind semantics are per board: re-selecting a board's own remote is
an accepted no-op; binding an already-bound board refuses with typed
=board-already-bound= (naming the board and its existing binding);
adopting a remote that another board already owns refuses with typed
=remote-board-in-use=.

** The daemon and IPC

#+begin_src sh
taskboard daemon            # boot the core, serve the per-db socket
taskboard status [--json]   # who serves this db + live sync status
taskboard tasks add "x"     # daemon running? served over it (no boot)
taskboard daemon stop       # graceful remote shutdown (exit 1 if none)
#+end_src

While the daemon runs, every core verb (=tasks=, =stacks=, =labels=,
=boards select/create/rename/publish=, =sync=) is *transparently*
served over the daemon's local socket — no per-command boot, and no
=instance-locked= friction; with no daemon answering, the invocation
boots in-process exactly as before (the observable contract is
byte-identical on both paths). Pre-core verbs (=login=, =logout=,
=config print=, =boards list=) always run client-side. =status= never
boots a core and never triggers a sync cycle: with a daemon it reports
={daemon: true, version, backend, pid, sync}= live; without, it names
the lock sidecar's holder pid. The socket is derived from the database
path (=taskboard.db= → the =taskboard.sock= sibling), owner-only on
unix, and self-heals after a crashed daemon (ADR 0012). A systemd
*user*-unit template ships in =contrib/taskboard.service= — the
comment block at the top is the install guide; =daemon stop= and
=systemctl --user stop taskboard= are both graceful.

=logout= deletes the stored app password and — under the auto backend
— clears the config's server/user keys, returning the install to
stand-alone (an explicit =backend = "nextcloud"= stays as written; the
next boot then fails loudly at credential resolution). A later =login=
to the same server resumes sync without data loss.

Connector-only verbs (=sync=, =daemon=, =boards list/select/publish=)
refuse with the typed =sync-disabled= error while no server is
configured; =boards create=, =stacks add=, and =tasks *= work under
every backend.

** Legacy path: sync-only install

First-run ceremony — =login= creates or updates =taskboard.toml= (the
example config above is optional; =login= writes =server_url= and
=username= itself) and stores the app password in the OS keyring:

#+begin_src sh
# Interactive: prompts for server, username, and the app password
# (echo-suppressed on a terminal; piped stdin works for scripts).
cargo run -p taskboard-app -- login
#+end_src

Headless variant: set =[nextcloud] credential_store = "env"= in the
config and export =TASKBOARD_APP_PASSWORD=<your-app-password>= —
=login= then succeeds with =stored: "env"= and no secret ever touches
a file.

Kiosk variant (no Secret Service): set =[nextcloud] credential_store =
"file"=. =login= generates the key file (=0600=) beside the database
and stores the password encrypted; unattended boots then work headless
with the key file present and fail typed without it. If the key
file's mode is ever weakened, taskboard refuses with
=KeyFileInsecureMode= — restore =chmod 600 <db-dir>/credential.key=
(the mode is never corrected automatically).

Then bind the installation to one Deck board and go:

#+begin_src sh
taskboard boards list          # remote ids feed select
taskboard boards select <id>
# A bare add lands in the single live board's Backlog stack (created
# on demand); aim elsewhere with --stack, or --board when several
# boards are live (several live boards without one = typed
# ambiguous-board):
taskboard tasks add "first task" --stack <stack-title>
taskboard sync                 # push now; durability is local immediately
taskboard tasks list
taskboard daemon               # headless sync loop until Ctrl-C/SIGTERM
#+end_src

Notes:

- *One core per database:* a second *core boot* (a second =daemon=, a
  REPL session) on the same database fails with the typed
  =instance-locked= error while a daemon runs — =daemon stop= first.
  One-shot core verbs do not contend: while a daemon serves the
  database they route over its socket (see [[*The daemon and IPC][The
  daemon and IPC]]). The lock is OS-released on process death; there is
  no stale-lock cleanup.
- *Offline-first:* =tasks add= (and every verb) is durable locally when
  the reply arrives; the push rides the next =sync= or the daemon. A
  verb serves the last synced state (the boot cycle's pull is given a
  bounded chance when it is still in flight) — run =taskboard sync= to
  see remote changes made elsewhere.
- *Scripting:* =--json= (global) prints typed JSON payloads on stdout;
  failures print ={"error":{"kind":"<kebab-case>"}}= on stderr and exit
  =1=. Idempotent repeats (=tasks done= twice) are successes. Exit code
  =130= is the daemon's second-signal force exit.
- *Multiple boards:* the one-board invariant is gone — boards bind
  independently (each board its own binding; see [[*Multiple boards and
  connectors][Multiple boards and connectors]]). =boards select= refuses a rebind
  only while the board is already bound elsewhere (=board-already-bound=
  names the board and its binding); a remote adopted by another board
  refuses (=remote-board-in-use=).
