#+title: ADR 0002: Dual-Tier Workspace Licensing
#+options: toc:nil

- *Date:* 2026-10-07
- *Status:* Accepted
- *Deciders:* Viktoria Pogrzebacz

* Context

The workspace contains both reusable library components and end-user
application binaries. A single license across all crates forces a trade-off:

- =AGPL-3.0-only= everywhere would prevent external Rust developers from
  importing =taskboard-domain= or the Nextcloud connector into permissive
  software, creating adoption friction.
- =MIT OR Apache-2.0= everywhere would allow third parties to take the
  finished Kiosk/Desktop application, modify it, and host it as a closed
  proprietary service without contributing back.

* Decision

*Dual-Tier Workspace Licensing Strategy*, defined at the crate level:

- *Permissive tier* — =MIT OR Apache-2.0= (SPDX:
  =MIT OR Apache-2.0=): =taskboard-domain=, =taskboard-state=,
  =taskboard-sync-nextcloud=, =taskboard-storage-sqlite=.
- *Copyleft tier* — =AGPL-3.0-only=: =taskboard-app=,
  =taskboard-ui-slint=, and any future presentation crates (e.g.,
  =taskboard-ui-iced=).

Implementation: canonical license texts in the repository root
(=LICENSE-MIT=, =LICENSE-APACHE=, =LICENSE-AGPL=); per-crate =license=
fields in each manifest; SPDX headers in every =.rs= file;
=cargo-deny= enforces dependency license compliance in CI.

* Embedded third-party assets

- The =pdf-export= feature (#624 stage B) embeds two font files in the
  =taskboard-app= binary: Noto Sans Regular/Bold (Google / the Noto
  project), licensed =OFL-1.1=. The OFL permits embedding and
  redistribution inside any software (the AGPL binary included); the
  verbatim license text and the provenance record live beside the
  files (=crates/taskboard-app/assets/fonts/=), which is the OFL's
  condition #2. The font is *data, not code* — the dual-tier rule
  (code must not flow between tiers) is unaffected, and the vendored
  files never touch =cargo-deny='s crate graph.

* Consequences

- *Positive:* Maximum ecosystem adoption for reusable libraries; the
  end-user product (including network-hosted kiosk services) is protected
  by the AGPL's source-publishing requirement.
- *Negative:* Contributors must pick the right SPDX header per crate; a
  new UI implementation must remember it lands in the copyleft tier;
  =cargo-deny= must be kept in sync with the allow-list.
- *Watch-out:* Code must not flow from the AGPL tier back into the
  permissive tier without a licensing decision.
