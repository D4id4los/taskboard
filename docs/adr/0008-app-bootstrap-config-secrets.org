#+title: ADR 0008: Application Bootstrap — In-Process Core, Config Hierarchy, Secret Resolution
#+options: toc:nil

- *Date:* 2026-10-10
- *Status:* Accepted
- *Deciders:* Viktoria Pogrzebacz

* Context

Phase 5 of the growth roadmap turns =taskboard-app= from a scaffold
binary into the reusable core every later frontend mounts: the daemon
now, Phase 6's CLI subcommands, and Phase 7's UI. Until now =main.rs=
was an empty shell; the actor spawn surfaces (engine, sync, storage)
are merged and final-for-now, and ADR 0007 left the channel-graph
ownership to this phase ("the Phase 5 bootstrap owns the system
broadcast sender").

Forces: tests cannot import from a =[[(bin)]]=; configuration must be
hierarchical (defaults → =taskboard.toml= → =TASKBOARD_*= env, the
settled house rule) while *never* carrying secrets; credentials need an
OS-side home that also works headless (the "[[file:../../.artifacts/taskboard-potential-improvements-backlog.org][Keyring fallback]]"
backlog entry demanded an explicit decision); and shutdown must be
graceful — the engine stopping on =Shutdown= *before* the sync actor's
final report lands would drop push evidence and re-POST creates after
restart (Deck has no idempotency keys, ADR 0007).

* Decision

** Lib + bin split, one =bootstrap= for every frontend

=taskboard-app= grows a library target (=taskboard_app=) exposing
=config=, =secrets=, =bootstrap=, and =cli=; =main.rs= is thin process
glue (clap parse → tracing → dispatch). One async
=bootstrap(config, credentials) -> App= owns the whole channel graph:
it validates, resolves credentials, builds the =DeckClient=, opens
sqlite (creating parent directories), and spawns storage → engine →
sync in that order — the failure-prone pure steps run before anything
spawns, and the only failing spawn (engine boot hydration) cleans up by
dropping the storage handle and joining its actor. =App= carries the
engine handle, the system broadcast sender, a retained sync-command
sender (the Phase 6 =SetBoard= seam — kept open, which is also why
actor shutdown keys on =Shutdown=, never on inbox close), the storage
handle, and all join handles. Channel capacities: system broadcast 64,
sync commands 32, sync reports 32.

** Strict tables: no secrets in TOML, mechanically

Every config table carries =#[serde(deny_unknown_fields)]= (per table,
*not* on the root — foreign tier-3 env profiles like
=TASKBOARD_IT_NEXTCLOUD_*= must stay ignorable). A =token= or
=password= key inside =[nextcloud]= therefore cannot even decode.
Required fields (=nextcloud.server_url=, =nextcloud.username=) are
=Option= in serde and checked by typed =AppConfig::validate()= —
figment's dynamic error strings are logged, never matched. Durations
are plain =u64= seconds fields; the default db path is
=dirs::data_dir()/taskboard/taskboard.db= (=~= is not expanded).

** Credential resolution: a port, two config-selected stores

The =CredentialStore= port has two implementations, selected
explicitly by =[nextcloud] credential_store=: =KeyringStore= (the OS
keyring, the default; entry =service "taskboard"=, account
="{username}@{host}"= — server-scoped so a config edit cannot silently
reuse another server's password) and =EnvCredentialStore= (reads
=TASKBOARD_APP_PASSWORD=; read-only; the sanctioned headless/CI escape
hatch). There is *no silent fallback of any kind*: on a machine without
a Secret Service the keyring store returns a typed =Backend= error
whose Display names the env alternative, and the operator opts in.
Secrets travel in a redacting =AppPassword= newtype (=Debug= prints
=[redacted]=, no =Display=, access only via =expose()=); the secret
never enters =AppConfig=. =store=/=delete= ship now for Phase 6's
=login=/=logout=. The encrypted-file store stays backlogged; the env
store's trade-off (process-scoped, visible to same-user tooling) is
recorded in the backlog entry.

** Graceful shutdown with an engine linger-drain

=App::shutdown()= runs the normative sequence: engine =flush()= →
broadcast =Shutdown= → await the sync actor's join bounded by
=[app] shutdown_timeout_secs= (10 s; abort at the timeout) → await the
engine join (bounded, abort as last resort) → drop the storage handle
and await its actor. =run_until_signal= awaits =ctrl_c= (plus SIGTERM
on unix); a second signal during the drain force-exits in =main=.

The one cross-crate semantic change: on =Shutdown= the engine no longer
returns immediately — it enters *drain mode*. It answers further
=Execute= with =EngineGone= and =Flush= with an immediate reply (the
pre-drain prefix is already settled), while *continuing to ingest
SyncReports* until the reports channel closes — which happens exactly
when the sync actor exits, because it owns the sender. The shutdown
ordering (actor joined before the engine join) makes the drain always
terminate. This closes the graceful-shutdown half of the
duplicate-create window (the hard-crash half remains backlogged).

** DeckClient redacts its credentials in =Debug=

=DeckClient= lost its derived =Debug= over the =credentials: String=
(the =user:app-password= pair); the manual impl prints
=credentials: "[redacted]"=. A leak-floor regression test (formatted
output must not contain the secret) guards both =DeckClient= and
=AppPassword= — the same redacting-=Debug= discipline applies to any
future secret-carrying type.

** CLI skeleton

clap with global =--config <path>=, =--version=, and one optional
subcommand =daemon=; no subcommand resolves =[app] mode= (=daemon= by
default; =desktop=/=kiosk= decode but fail with a typed
=ModeNotImplemented= until Phase 7 replaces the arm). Phase 6 grows the
=Command= enum without touching =main='s dispatch shape.

** Dependencies

Workspace-pinned once in the root =Cargo.toml=: =clap 4= (derive),
=dirs 6=, =keyring 3= (=default-features = false=; platform stores
feature-gated via the workspace's first target-specific deps:
linux =sync-secret-service + crypto-rust=, windows =windows-native=,
macOS =apple-native=). =rpassword= is deliberately deferred to Phase 6
— Phase 5 has no interactive prompt, and an unused dependency trips the
hygiene gate. *Linkage note:* the linux =sync-secret-service= feature
routes through =libdbus-sys=, linking the system =libdbus-1= C library
— every desktop Linux ships it, and aarch64 cross builds need the
target sysroot's =libdbus-1-dev= plus a cross pkg-config, the same
class of C-toolchain requirement the ring build (rustls) already
imposes. The pure-Rust zbus path (=async-secret-service=) only exposes
async APIs and would rework the sync store; revisit if the release
pipeline ever drops system dbus.

* Consequences

- Every Phase 6 subcommand boots the same in-process core and every
  Phase 7 UI mounts beside the daemon loop — one bootstrap, N
  frontends (the roadmap's "in-process core" decision).
- The engine's drain semantics are additive; the phase 3 snapshot suite
  is untouched and the G-series pins the contract in both directions.
- Shutdown is bounded everywhere; aborting the sync actor is equivalent
  to a crash *between* cycles from the outbox's perspective (the
  storage actor is only stopped after the engine stopped issuing
  batches, so no transaction is killed mid-flight).
- CI's docker tier (nextcloud-integration.yml) now runs the app crate's
  =it_nextcloud_docker= journey — the automated Phase 5 exit demo; the
  literal M1 checkpoint is the tier-3 runbook against the live server.
- Interim multi-process stance: nothing here prevents two =taskboard=
  processes opening one database; the single-connection WAL pool +
  busy-timeout queues writers safely until Phase 6's instance lockfile.
