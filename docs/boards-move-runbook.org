#+title: taskboard Board-Move Runbook
#+options: toc:t

Moving a board from Deck to the files tier (=boards move=, D-BF11)
and running Deck boards and files boards side by side. Every step
names the code symbol it exercises.

*Before the first move*: upgrade every device. An older build ignores
the move marker and folds the subtree as a second board.

* 1. Moving a board

Stop editing the board on this device, then run
=boards move <board-uuid> --to-files=. Requires =[files_sync] enabled=
(otherwise =MoveError::FilesSyncDisabled=).

| Step | Effect | Symbol |
|---+---+---|
| 1 | Final Deck cycle, then the outbox must be quiet | =MoveWorld::pull_deck=, =MoveError::OutboxNotQuiescent= |
| 2 | Publish the snapshot floor at =boards/<board-uuid>/= | =publish_move_floor= |
| 3 | Retire the Deck binding (=UnbindBoard=) | =MoveStep::DeckRetired= |
| 4a | Write =boards/<board-uuid>/move.json=, the commit point | =publish_move_record=, =MoveStep::CommitPublished= |
| 4b | Mark the Deck sidecar, then bind files (=BindBoard=) | =write_move_marker=, =MoveStep::FilesAssigned= |

The position is derived by =derive_move_stage= from the binding row
and =probe_move_subtree=; nothing is checkpointed. After any
interruption, rerun the same command. A rerun after the commit does
nothing.

* 2. The undo window

Open only at =MoveStage::DeckRetired= (retired, not yet committed),
which in practice means a run that was interrupted between steps 3 and
4. =boards move <board-uuid> --undo= restores the Deck binding and runs
a Deck cycle. The coordinates come from the subtree's =moved_from= and
the connector configured for that server; with no such connector the
refusal is =MoveError::UndoCoordinatesLost=.

The commit record closes the window, before the files binding is
written: =MoveError::UndoClosed=.

After an undo the marked subtree is inert: with no commit record, no
device adopts it or mints a board from it. A later move republishes it.
Deleting it by hand is optional.

* 2a. A device was offline during the move

On its next files cycle a device still bound to the moved Deck board
(same server and board id) records =BoardMoveFinding::Adopting= and logs
a warning, then =plan_board_adoption= re-keys its rows onto the mover's
ids and swaps the binding in one transaction (=AdoptMovedBoard=). The
ordinary lane then pulls first and publishes after, so its offline
edits and cards reach the other devices. =status= shows =adopting=, then
=adopted=. Queued Deck ref-deletes are dropped; at worst a duplicate
card stays visible.

Refusals leave the Deck binding in place and retry every cycle:
=refused_collision= (a published id already exists locally, typically
a duplicate from an older build; delete it), =refused_record_malformed=
and =refused_record_newer= (upgrade this app).

A device that had already unbound its copy does not adopt: that copy
stays a separate board, and the move arrives as a new board.

* 2b. A device without files sync

The mover leaves a marker in the Deck sidecar. The device's =status=
line and board caption report =moved_to_files=. It does not adopt until
=[files_sync]= is enabled; until then it syncs a frozen Deck board.

* 3. Mixed-fleet operation

Each board has exactly one owner, its binding row
(=BoardOwnershipMap=). Deck boards sync through their Deck connector
and files boards through =files-sync=, under one account. During a
move the row goes Deck, then unbound, then files, so two owners are
not representable.

* 4. Retiring the Deck board on the server

The ceremony never deletes the Deck board. Delete it yourself only
after every device reports =adopted=. A device still bound to a deleted Deck
board treats the absence as a real deletion and tombstones the board.
Recovery for files-side losses is in =files-sync-runbook.org= §2.

* 5. The reverse direction is fenced

=boards move --to-deck= always refuses with =MoveError::ReverseFenced=
(ruling Q4). Changing that takes a new design round.

* 6. Symptoms

** =OutboxNotQuiescent=
*** Cause
Edits are still queued for this board.
*** Recovery (matches the code's semantics)
Stop editing, run =sync=, rerun the move.
*** What NOT to do
Do not =boards unbind= to clear the queue; that strands the ops.

** =FilesSubtreeForeign=
*** Cause
The target subtree has an identity but no directory for this device.
*** Recovery (matches the code's semantics)
Find which device wrote it before doing anything. The ceremony will
not write into it.

** =StrandedOps=
*** Cause
An edit landed between the guard and the retirement. The Deck binding
is already retired at this point.
*** Recovery (matches the code's semantics)
Run =--undo= to restore the Deck binding, =sync=, and rerun the move.

** =DeckMarkerFailed=
*** Cause
The commit record is written but the Deck sidecar could not be updated
(server error, or a sidecar this build cannot read).
*** Recovery (matches the code's semantics)
Rerun the move; only the marker and the binding remain.
