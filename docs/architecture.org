#+title: taskboard System Architecture
#+options: toc:t

*Project:* Multi-Actor, Channel-Driven Kiosk & Desktop Task Management
Application

*Namespace:* =taskboard-*=

*Target HW Platform:* Low-power ambient display devices (Kiosk Mode) &
interactive Desktop Workstations

*Target OS Platforms:* Primary Linux & Windows, with second-tier MacOS
support.

* Executive Summary

The =taskboard= application is a cross-platform task management and
reminder system. It ships three process modes (=AppMode=,
=config.rs=): *Daemon* (the default — a headless core serving the CLI,
the interactive REPL, and remote clients over IPC), *Desktop* (the
shipped Slint GUI, ADR 0015), and *Kiosk* — planned for the kiosk wave
(the accepted kiosk-wave decisions of 2026-10-16) and refused at the
daemon mode gate until it lands; no frontend routes
to it today. The two-mode product vision behind the mode axis remains:

1. *Passive Kiosk Mode (vision):* running on low-power hardware
   attached to an office display, providing continuous, resilient
   visual output with minimal user interaction.

2. *Interactive Desktop Mode (shipped):* running on standard desktop
   PCs to actively manage tasks, workflows, and visual display
   preferences.

To guarantee zero frame-drops, non-blocking rendering, high system
resilience, and maximum flexibility across different GUI frameworks and
backend services, the application employs a *Headless Core with an
Event-Driven Multi-Actor Architecture* built on modern async Rust.

The product shape is *stand-alone by default, sync when configured*
(ADR 0010): the app is a fully local task manager with no server
configured — fresh installs default to it — and Nextcloud sync is the
first optional connector, selected by the =[sync] backend= config
value (=standalone= | =nextcloud=; absent means auto: =nextcloud= iff
=[nextcloud] server_url= is present). Local content migrates onto a
remote board via =boards publish= or =boards select
--bind-local-board=.

** Separation of Concerns & Unidirectional Data Flow

The system strictly isolates presentation, state processing, network
communication, and disk storage.

- User interactions or visual timers never mutate state in-place.
- Components publish intents over asynchronous channels.
- State transitions are centrally processed by a State Engine, producing
  immutable snapshots for consumption.

** Async-by-Default Execution

All network calls (Nextcloud Deck OCS REST API) and local disk operations
(SQLite) run in isolated background tasks on the Tokio async runtime.
Heavy processing, polling, or network timeouts cannot block the UI
rendering loop.

** Framework-Agnostic "Thin Client" UI

Slint 1.18.1 is the shipped UI framework (ADR 0015), and the GUI layer
operates as a dumb presentation client over it. It relies on standard
Rust primitives to communicate with the core engine: lock-free
=ArcSwap<AppState>= reads for state, =EngineSignal= /
=SystemEvent= broadcast receivers drained by the UI's repaint timer
(a Slint =Timer= that also wakes on the wall-minute boundary), typed
=UiSettings= handed over from the app side (config is read there via
figment — never inside the UI crate), and user intents dispatched as
typed =StateCommand=s on the state-command =mpsc=, drained by the
bootstrap-owned UI-command forwarder. No IO crates, no business
logic, no state mutation inside the UI.

The framework-swap seam survives as the *crate boundary*
(=taskboard-ui-slint= contains presentation logic only), not as an
unexercised aspiration: =taskboard-app= depends on the UI crate and
its other actors never do, so a future frontend would be a new
workspace member behind the same hand-over contract.

* Inter-Component Communication Protocol

Components communicate through typed channels and shared atomic pointers,
avoiding central runtime bottlenecks.

| Communication Path | Mechanism / Type | Description & Purpose |
|---+---+---|
| *UI → State Engine* | =tokio::sync::mpsc= | Sends user intent commands (=StateCommand=) asynchronously; the mpsc is drained by the bootstrap-owned UI-command forwarder (=taskboard_app::ui::spawn_ui_command_forwarder=: =recv()= → =EngineHandle::dispatch= over the =CommandSink= trait, dropped-command logging, capacity 64). |
| *State Engine → UI (Read)* | =arc_swap::ArcSwap<AppState>= | Provides lock-free, zero-contention state inspection during UI repaints. |
| *State Engine → UI (Signal)* | =tokio::sync::broadcast= | Emits lightweight triggers (=EngineSignal::StateUpdated=) to prompt GUI repaints. |
| *UI/CLI → State Engine* | =tokio::sync::mpsc= + =oneshot= | =EngineEnvelope::Execute= carries a =StateCommand= payload with an optional oneshot receipt (typed =Result<CommandOutcome, ExecuteError>=; a received reply implies durability). =EngineEnvelope::Flush= is the reply-less dispatch durability barrier (CLI exit). |
| *State Engine → Sync Actor* | =tokio::sync::mpsc= | =SyncCommand= nudges: =SyncNow= (forwarded iff an accepted batch enqueued an op, or on =RequestSync= / =NetworkRestored=) and =SetBoard= (pull-target selection, Phase 6's CLI path). The actor dedupes =SyncNow= while a cycle runs. |
| *Sync Actor → State Engine* | =tokio::sync::mpsc= | =SyncReport::{Completed, Failed}= ingestion through the conflict pipeline (ADR 0007's evidence-then-verdict: =Completed= carries snapshot + validators + pushes + =read_at=; =Failed= carries the pushes that landed before the abort). |
| *Sync Actor → Everyone* | =tokio::sync::broadcast= | Produces =SystemEvent::NetworkLost= / =NetworkRestored= (this actor is the network authority) and consumes only =Shutdown= from the same channel. |
| *Sync Actor → State Engine (reads)* | domain port =SyncStateReader= | =EngineEnvelope::ReadState= envelope behind the port: the cycle reads outbox, bindings, and validators via the engine, never direct SQL (ADR 0005/0007). |
| *Actors ↔ Actors* | =tokio::sync::mpsc= | Direct point-to-point command delivery between backend actors (e.g., State Engine → Storage via the =TaskRepository= port adapter). |
| *System Notifications* | =tokio::sync::broadcast= | Broadcasts global status changes (=SystemEvent::NetworkLost=) to all interested actors. |
| *CLI ⇄ Daemon (local socket)* | =interprocess= local sockets + length-framed JSON | Transport-only reuse of =dispatch_line= (ADR 0012): the daemon serves the per-database socket (<db>.sock sidecar); a CLI invocation relays raw argv and prints the daemon's rendered ={code, out, err}= verbatim — byte-identical to the in-process dispatch. Versioned envelopes (v1); one request per connection; serial execution on one dispatcher task. |
| *Asynchronous Queries* | =tokio::sync::oneshot= | Embedded inside an =mpsc= message payload for direct, async request-response cycles. Payloads are pure domain types; the channel-bearing envelope is declared by the actor crate (payload/envelope split, ADR 0004). |
| *REPL loop ⇄ editor thread (disposition)* | =tokio::sync::mpsc= + embedded =oneshot= (ADR 0014) | The per-line handshake: the editor thread delivers one =LineEvent=, then awaits the loop's =Disposition= (=Next=, or =Prompt{label, kind, reply}= for a follow-up read). Masked reads (=rpassword=) run on the reader thread; answers ride the oneshot and never enter history or completion. Capacity-1 channels keep the alternation strict — the race-free property. |
| *Session ⇄ core (connector ceremonies)* | =App::attach_connector= / =App::detach_connector= + config refresh (ADR 0014) | An in-session =connect= line runs the shared ceremony through the session's prompt reader, refreshes the session config through the boot resolution, detaches any live connector, and attaches a fresh one from the refreshed config; =logout= is the mirror (local teardown → detach → refresh). Verb bodies are frontend-agnostic functions the Phase 7 GUI reuses. |

All inter-actor channels — the system broadcast, both sync =mpsc=
pipes, and the storage/engine command inboxes — are *bootstrap-created*
and owned by =taskboard_app::bootstrap= (ADR 0008); actors receive
their halves as injected constructor arguments and never construct
channels between themselves.

* Cargo Workspace Topology

To enforce strict boundary checks at compile time and accelerate build
speeds, the project is structured as a Cargo workspace with explicit
dependency hierarchies.

** Crate Roles & Dependencies

1. *taskboard-domain* — Pure data types (the canonical =Board= / =Stack= /
   =Task= / =Label= entity set with per-field write clocks; =Project= is
   superseded by =Board= and =UserPreferences= is deferred), inter-actor
   message payloads (=StateCommand=, =SystemEvent=, =SyncCommand=,
   =SyncReport=), the persistence port (=TaskRepository=), and the pure
   sync conflict policy (=apply_sync_report=, ADR 0004). The policy is
   executed by the *state engine*, never by the sync actor. Dependencies:
   minimal (=serde=, =chrono=, =uuid=, =thiserror=, =tracing= for
   pure-macro event instrumentation of the conflict policy — no I/O, no
   subscriber, no runtime). Zero UI, network, database, or
   async-runtime dependencies; async ports return a
   hand-rolled =BoxFuture=. Channel-bearing envelopes (e.g. a =Flush=
   barrier wrapping =oneshot::Sender=) live in the actor crates that own
   the channels — domain owns only the pure payloads.

2. *taskboard-state* — Single source of runtime truth (ADR 0006). Runs
   the State Engine actor: a sequential command loop over the domain's
   pure transition functions (=plan_command= for local commands,
   =apply_sync_report= for sync ingestion). Memory advances only by
   interpreting the action batches that were durably applied through the
   =TaskRepository= port (consumed as =Arc<dyn TaskRepository>—
   production wires the sqlite actor via a port adapter); after each
   interpreted batch it publishes the =AppState= projection through
   =ArcSwap<AppState>= and broadcasts =EngineSignal::StateUpdated=.
   Inbox: =EngineEnvelope::{Execute (oneshot receipt), Flush (durability
   barrier)}=; it also ingests =SyncReport=s and =SystemEvent=s, and
   forwards =SyncNow= nudges to the sync actor. Command *semantics*
   (rejections, no-ops, cascades) live in the domain; this crate owns
   channels, publishing, and sequencing only. Dependencies:
   =taskboard-domain=, =arc-swap=, =chrono=, =tokio=.

3. *taskboard-sync-nextcloud* — The sync actor (ADR 0007): a scheduled
   cycle that reads the engine's persisted state through the domain's
   =SyncStateReader= port (never direct SQL, ADR 0005), pushes the
   coalesced outbox via the pure =plan_pushes= planner + push executor
   (binding overlay, fetch-before-write, typed error classification),
   pulls the bound board through three conditional reads into a complete
   =RemoteBoardSnapshot= (both stack listings; per-card detail refresh),
   and reports =SyncReport=s with evidence-then-verdict semantics. Owns
   the offline FSM: broadcasts =SystemEvent::NetworkLost/Restored=,
   failure backoff, cycle-in-flight dedupe; =SetBoard= sets the pull
   target (binding happens by adoption in the engine). Stateless across
   restarts except the injected =DeckClient=. Dependencies:
   =taskboard-domain=, =reqwest=, =serde=, =serde_json=, =chrono=,
   =tokio=, =thiserror=, =tracing=.

4. *taskboard-storage-sqlite* — Manages local SQLite disk persistence.
   Ensures the app boots immediately with cached data if network
   connectivity is lost. Normalized schema (boards/stacks/tasks/labels,
   =task_labels= join, =outbox=, =sync_metadata=, =sync_status= singleton)
   applied at boot from embedded migrations; WAL + =synchronous=NORMAL= on
   a single connection; =SqliteTaskRepository= implements the domain's
   =TaskRepository= port (one transaction per batch) behind the
   =StorageCommand= actor inbox (=StorageHandle=, oneshot replies —
   ADR 0005). Compile-time checked =query!= SQL against the committed
   =.sqlx/= offline cache; refresh it with =scripts/sqlx-prepare.sh= after
   touching a query or migration. Dependencies: =taskboard-domain=,
   =sqlx=, =tokio=.

5. *taskboard-ui-slint* — The Slint presentation layer (ADR 0015). The
   module map: =theme= (the token module — colour/text-role/spacing
   globals with closed text roles — plus the bundled tri-licensed
   fonts with runtime registration), =actions= + =keymap= +
   =resolver= (action registry with reserved global actions,
   keymap-as-data with standard/emacs/vi presets and drop-and-warn
   merge validation, pure stroke resolver with chords/prefixes/vi
   modes/masking), =adapter= (the root-FocusScope capture
   interception) + =menu= (the generated action menu), =router= /
   =view_state= (the Board → StackDetail → TaskDetail view machine),
   the L1 widget / L2 composition / L3 view component layering
   under =ui/=, and =presentation= (pure display helpers reusing the
   domain's overdue/due-soon semantics) + =responsive= (unscaled
   breakpoints). State enters via lock-free =ArcSwap<AppState>=
   loads and the broadcast receivers; config arrives as typed
   =UiSettings= — no IO crates, no business logic, no state
   mutation (AGPL-3.0-only, with the ADR 0003 =unsafe= exception for
   Slint-generated code). Dependencies: =taskboard-domain=,
   =slint= (default renderer features + the additive
   =unstable-fontique-011= font-registration feature), =arc-swap=,
   =tokio= (channel types only — the mandated fabric, not an IO
   dependency), =chrono=, =thiserror=, =tracing=; =slint-build= at
   build time (the UI codegen); dev-only: =i-slint-backend-testing=
   (exact pin), =insta=, =proptest=, =png=, =uuid=, =serde=.

6. *taskboard-app* — The bootstrap library (ADR 0008) plus the thin
   =taskboard= binary. The library owns =config= (figment hierarchy
   defaults → =taskboard.toml= → =TASKBOARD_*= env, strict tables —
   secrets in TOML cannot decode; the config *file* resolution order is
   =--config= > =TASKBOARD_CONFIG= > the XDG candidate
   =$XDG_CONFIG_HOME/taskboard/taskboard.toml= when it exists >
   =./taskboard.toml=, absent files tolerated), =secrets= (the =CredentialStore=
   port with the keyring and env stores, config-selected, no silent
   fallback; redacting =AppPassword=), =bootstrap=: one async fn
   that wires the whole channel graph (all channel halves created here,
   ADR 0007's handoff note; under the resolved =standalone= backend the
   sync connector is *not* spawned and its channel halves are dropped —
   the engine sees the closed-channel world it already handles, ADR
   0010) and returns the =App= handle shared by every frontend, =lockfile= (the per-database instance lock — an
   OS-released advisory lock on a =<db>.lock= sidecar acquired before
   the db open, ADR 0009), and =commands= (ADR 0009): the operator
   CLI's typed handlers — =connect= (introduces a connection; =login=
   is its deprecated alias, ADR 0014), =logout=, =boards= (list/select/
   create/publish/rename), =stacks= (add/rename/delete/move), =tasks=
   (list/add/done/move/edit/delete/label/unlabel), =labels=
   (list/add/edit/delete), =sync=, =config print= — with the =--json=
   output contract (typed projections on stdout, kebab-case error
   envelopes on stderr). Task selectors cascade exact uuid → unique
   ≥8-char prefix → exact title; destructive verbs are
   confirmation-free (scripting-first) with idempotent repeats; board
   titles are locally editable (the field-wise title merge of the ADR
   0004 amendment). =main.rs= is dispatch + exit codes only.
   =App::shutdown()= is the graceful sequence (flush → =Shutdown=
   broadcast → bounded actor joins with the engine's linger-drain →
   storage join). =repl= (ADR 0011): the interactive session frontend —
   bare =taskboard= on a TTY opens a parted-style shell over *one*
   booted core (boot-once, one lock epoch, graceful shutdown at
   =exit=/Ctrl-D); each line is shell-word-split, parsed as one CLI
   invocation (=Cli::try_parse_from=), and routed by
   =dispatch_line= through the same =*_on(&App)= verb bodies the
   one-shot wrappers call; =connect=/=login=/=logout= are intercepted
   by the session loop as ceremonies (ADR 0014: config refresh +
   connector attach/detach against the running core), and the daemon
   IPC server refuses them as terminal-bound before dispatch. The
   rustyline editor lives on a dedicated thread streaming =LineEvent=s
   through a bounded channel and answering the loop's per-line
   =Disposition= handshake (masked reads included), so no async
   runtime worker ever blocks on stdin. =ipc= (ADR 0012): the daemon
   IPC frontend — the third frontend over the shared seam. The server
   binds the per-database socket (=<<db>.sock= sidecar, stale-artifact
   recovery, unix 0600), accepts connections concurrently, and executes
   requests serially on one dispatcher task (engine fairness); the
   client relays rendered ={code, out, err}= verbatim with typed
   =NoDaemon=/=IpcTransport=/=IpcVersion= failures; =route_for_ipc=
   picks each verb's transport lane (Local / IpcOrLocal / IpcOnly) and
   =status=/=daemon stop= are the operator verbs over the wire.
   =ui= (ADR 0015): the GUI lifecycle — D4 bare-invocation routing
   (=mode = "desktop"= boots the Slint GUI regardless of TTY;
   =AppMode= is frontend selection, so only =Daemon=+TTY falls to
   the REPL; otherwise the daemon lifecycle), the UI-command
   forwarder (=spawn_ui_command_forwarder= over the =CommandSink=
   trait), and =resolve_ui_settings= (the figment =[ui]= table into
   typed =UiSettings=; keymap findings surface as startup warnings
   and never block start). The =[ui]= config surface: =scale=
   (0.5–3.0, typed-validated) and =keymap.preset= /
   =keymap.overrides=.
   Dependencies: all workspace
   crates, =figment=, =clap=, =keyring= (platform features via
   target-specific deps), =rpassword=, =fd-lock=, =toml_edit=,
   =serde_json=, =dirs=, =color-eyre=, =tracing=, =tokio=, =rustyline=,
   =shell-words=, =interprocess=.

* Versioning

The project uses a single global semantic version shared by all crates:

#+begin_example
taskboard v0.2.3
├── crates/taskboard-domain         @ 0.2.3
├── crates/taskboard-state          @ 0.2.3
├── crates/taskboard-sync-nextcloud @ 0.2.3
├── crates/taskboard-storage-sqlite @ 0.2.3
├── crates/taskboard-ui-slint       @ 0.2.3
└── crates/taskboard-app            @ 0.2.3
#+end_example

The version is defined once in =[workspace.package] version= in the root
=Cargo.toml=; every member crate inherits it via =version.workspace = true=.
Releases are cut exclusively with =./scripts/bump_version.sh
<major|minor|patch>= (see =docs/coding_guidelines.org=).
