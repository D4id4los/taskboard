#+title: taskboard System Architecture
#+options: toc:t

*Project:* Multi-Actor, Channel-Driven Kiosk & Desktop Task Management
Application

*Namespace:* =taskboard-*=

*Target HW Platform:* Low-power ambient display devices (Kiosk Mode) &
interactive Desktop Workstations

*Target OS Platforms:* Primary Linux & Windows, with second-tier MacOS
support.

* Executive Summary

The =taskboard= application is a cross-platform task management and
reminder system. It ships three process modes (=AppMode=,
=config.rs=): *Daemon* (the default — a headless core serving the CLI,
the interactive REPL, and remote clients over IPC), *Desktop* (the
shipped Slint GUI, ADR 0015), and *Kiosk* — the appliance (ADR 0016): the daemon core plus the
display-gated fullscreen window, with a loud headless fallback that
keeps serving over IPC — and the window is now the passive ambient
view: the =KioskMode= / =KioskRotation= display-mode state machine
(=crates/taskboard-ui-slint/src/view_state.rs=) rotates the pinned
board's kanban reading and the today view's upcoming reading on a
UI-side dwell timer, with zero engine commands; the wave's on-device
budget verdicts are recorded in the kiosk wave exit report
(=.artifacts/reports/2026-10-27-kiosk-wave-exit-report.md=). The two-mode product vision behind the mode axis remains:

1. *Passive Kiosk Mode (shipped):* running on low-power hardware
   attached to an office display, providing continuous, resilient
   visual output with minimal user interaction.

2. *Interactive Desktop Mode (shipped):* running on standard desktop
   PCs to actively manage tasks, workflows, and visual display
   preferences.

To guarantee zero frame-drops, non-blocking rendering, high system
resilience, and maximum flexibility across different GUI frameworks and
backend services, the application employs a *Headless Core with an
Event-Driven Multi-Actor Architecture* built on modern async Rust.

The product shape is *stand-alone by default, sync when configured*
(ADR 0010): the app is a fully local task manager with no server
configured — fresh installs default to it — and Nextcloud sync is the
first optional connector, selected by the =[sync] backend= config
value (=standalone= | =nextcloud=; absent means auto: =nextcloud= iff
=[nextcloud] server_url= is present). Local content migrates onto a
remote board via =boards publish= or =boards select
--bind-local-board=.

** Separation of Concerns & Unidirectional Data Flow

The system strictly isolates presentation, state processing, network
communication, and disk storage.

- User interactions or visual timers never mutate state in-place.
- Components publish intents over asynchronous channels.
- State transitions are centrally processed by a State Engine, producing
  immutable snapshots for consumption.

** Async-by-Default Execution

All network calls (Nextcloud Deck OCS REST API) and local disk operations
(SQLite) run in isolated background tasks on the Tokio async runtime.
Heavy processing, polling, or network timeouts cannot block the UI
rendering loop.

** Framework-Agnostic "Thin Client" UI

Slint 1.18.1 is the shipped UI framework (ADR 0015), and the GUI layer
operates as a dumb presentation client over it. It relies on standard
Rust primitives to communicate with the core engine: lock-free
=ArcSwap<AppState>= reads for state, =EngineSignal= /
=SystemEvent= broadcast receivers drained by the UI's repaint timer
(a Slint =Timer= that also wakes on the wall-minute boundary), typed
=UiSettings= handed over from the app side (config is read there via
figment — never inside the UI crate), and user intents dispatched as
typed =StateCommand=s on the state-command =mpsc=, drained by the
UI-command forwarder (spawned by =taskboard_app::ui= in
=run_desktop=). No IO crates, no business logic, no state mutation
inside the UI.

The framework-swap seam survives as the *crate boundary*
(=taskboard-ui-slint= contains presentation logic only), not as an
unexercised aspiration: =taskboard-app= depends on the UI crate and
its other actors never do, so a future frontend would be a new
workspace member behind the same hand-over contract.

** Board Selection is Caller-Owned

With N live boards there is no engine-side "the selected board": the
State Engine holds no selection state (DF-2 — selection never enters
the domain crate). Each frontend owns its own:

- *CLI*: the =--board <uuid>= flag on the board-scoped verbs; when
  omitted, the single live board is resolved at invocation — with zero
  or several live boards the verb refuses with the typed
  =ambiguous-board= error listing the candidates.
- *REPL*: =ReplSession.current_board= (set by =boards use <uuid>=);
  later board-scoped lines pre-fill =--board= from it.
- *UI*: =ViewState.board= (refresh-time normalization re-seeds it from
  =presentation::live_board= when absent or no longer live); the board
  switcher — =select_board= and the =board.next/previous= walk,
  mirroring the stack switcher — is its only mutator. Switching is
  pure view state — nothing is dispatched to the engine. The
  daily-driver wave's =ViewId::Today= is the one cross-board surface:
  it renders every live board at once, and selection-follows-focus
  retargets =ViewState.board= from the focused row; it is the desktop
  default start view (kiosk keeps Board via =UiSettings.kiosk=). The
  kiosk appliance pins the board through =[kiosk] fixed_board=
  instead — resolved typed at boot (=resolve_fixed_board=); the
  caller-owned rule stands, the pin is the deployment's caller
  decision.

** The app-data sidecar

The daily-driver wave split each mergeable task field's sync lane by
its =TASK_FIELDS= manifest row (=FieldFamily=): nine fields ride
Deck's *native* card slots (=title=, =description=, =due=, =order=,
=archived=, …, plus =scheduled= wherever the server's Deck version
exposes =CARD_STARTDATE= — detected once per sync actor via the
=capabilities.rs= probe), and three ride the *app-data sidecar
document* (=effort=, =importance=, =urgency=, plus =scheduled=
elsewhere and the reminder-rule registry). The document is one JSON
attachment (=?taskboard-appdata.json=) on one reserved carrier card
per board (exact title =[taskboard] app-data=), maintained by the
connector actor's anchor ceremony (lazy creation, adoption, pick,
restore-then-replace) and flushed each cycle as a read-modify-write
union — versioned envelope, embedded-clock last-writer-wins,
unknown content preserved verbatim (a v1 device acts as a
transparent relay, never a destroyer), the reserved key space
(=proofs= / =settings= / =task-kind= / =respite= / =recurrence=)
kept out of v1's reach.

Evidence travels the existing =SyncReport= path: each completed
cycle reports =AppDataEvidence= per board; the engine derives
per-board sidecar health onto =SyncStatus.sidecar= (memory-only),
and an unreadable document surfaces *loudly* — the CLI =status=
warning (=sidecar.reason=, additive) and the UI's sidecar badge —
with the format-too-new fence never re-encoding the document
downstream. Device-local things never enter the document:
=AdhocAlarm=s and the delivery/snooze/mute records stay in the
local SQLite tables (0004/0008). Accepted limitation: a card moved
between boards loses its app-side fields (the document is
per-board; issue #350 tracks the repair).

** The kiosk appliance and its surfaces

The kiosk wave's one architectural story: one process = the daemon
core *plus* a fullscreen presentation that degenerates to a passive
ambient display — and every kiosk subsystem hangs off that shape
without a new channel.

- *The appliance shape* (ADR 0016): bare =kiosk= is TTY-independent
  routing to one lifecycle = the =daemon_lifecycle= head (storage,
  engine, system-event logger, per-database IPC server) + the ADR
  0015 hand-over with =UiSettings.kiosk = true=. The display gate is
  evaluated before any slint call (=kiosk_start= in
  =crates/taskboard-app/src/ui.rs=: =KioskStart::{Appliance,
  Headless}=): with no display the same invocation falls back loudly
  to headless serving over IPC. Window-close, signals, and =daemon
  stop= all converge on the shared serve-drain-shutdown tail
  (=serve_and_shutdown= / =drain_and_shutdown= in =main.rs=). No
  kiosk IPC verb exists — the appliance is entered at boot only
  (ADR 0016's Option B fence, unfired).
- *The deployment profile*: =[kiosk]= is a typed table under
  =deny_unknown_fields= (=KioskSection= in =config.rs=).
  =fixed_board= resolves through =AppConfig::resolve_fixed_board= —
  absent pin + 1 live board = that board; absent pin + ≥ 2 live
  boards = the typed =kiosk-pin-required= refusal (the K13 ruling
  that replaced the pre-K13 "rotation scope" idea: a multi-board
  ring is explicitly out of scope); an unknown/dead pin = the typed
  =unknown-fixed-board= error. =[kiosk.rotation]= (=#363=) carries
  =modes= (≥ 2 distinct =board|=today= entries) and =dwell_secs=
  (floor =KIOSK_ROTATION_MIN_DWELL_SECS= = 10 s — refused, never
  clamped); every invalid value is a typed config error, never a
  silent default. Deployment rides =contrib/taskboard-kiosk.service=
  (=Restart=always=, the config file's =mode = "kiosk"= as the only
  mode authority, the seat's display env imported) and the bring-up
  runbook (=docs/kiosk_bringup_runbook.org=).
- *The ruled renderer posture* (ADR 0016's 2026-10-21 amendment):
  the shipped winit + femtovg stack renders through Mesa software GL
  on the target class; the permission-based fallback (the appliance
  user deliberately out of =video= / =render=) is the sanctioned
  contract — no =LIBGL_ALWAYS_SOFTWARE= pin, no build flip.
- *The metrics surfaces*: per-board cumulative sync counters ride the
  existing =SyncReport= ingestion onto =SyncStatus.counters= (the
  =aggregate()= fold, domain =state.rs=), and the engine activity
  counters live on the handle side (=EngineMetrics= in
  =taskboard-state=, surfaced in =status='s =engine= object) — never
  in =AppState=. Both are read lock-free by the CLI =status= and the
  web dashboard. No new channel, no new wake source.
- *The credential file store*: the third =CredentialStore=
  implementation behind the unmoved port (=secrets.rs=), selected by
  =[nextcloud] credential_store = "file"= — a generated =0600= key
  file beside the database plus ChaCha20-Poly1305 AEAD envelopes
  under =<db-dir>/credentials/=, typed failure fences for every
  corruption shape, no silent fallback (the ADR 0008 amendment).
- *The web dashboard*: an app-layer hyper 1.x server on the same
  daemon lifecycle (=[web]=, =WebSection= in =config.rs= —
  =enabled= / =bind= (loopback default =127.0.0.1:8787=) /
  =refresh_secs= (self-DoS floor 5) / =token=). The capability-token
  URL space (=/d/<token>/…=) gates a non-loopback bind — a LAN bind
  with no resolvable token refuses at boot. One lock-free
  =ArcSwap= load plus one metrics read per request; meta-refresh
  polling; the second dumb presentation client over the same state
  read (the framework-swap seam's second exercise — ADR 0015's rule
  holds over HTTP).
- *The ambient view*: =KioskMode::{Board, Today}= rotation driven by
  =KioskRotation::tick= and the adapter-owned dwell timer in the UI
  crate (=crates/taskboard-ui-slint/src/lib.rs=) — pure view state,
  zero engine commands; no capture affordance is reachable in a
  kiosk mode and the notification surface stays empty; the overdue
  banner and the offline tone carry across flips; the desktop paths
  are byte-identical when the rotation table is absent.

* Inter-Component Communication Protocol

Components communicate through typed channels and shared atomic pointers,
avoiding central runtime bottlenecks.

| Communication Path | Mechanism / Type | Description & Purpose |
|---+---+---|
| *UI → State Engine* | =tokio::sync::mpsc= | Sends user intent commands (=StateCommand=) asynchronously; the mpsc is drained by the UI-command forwarder (=taskboard_app::ui::spawn_ui_command_forwarder=: =recv()= → =EngineHandle::dispatch= over the =CommandSink= trait, dropped-command logging, capacity 64), spawned in =run_desktop=, not by bootstrap. |
| *State Engine → UI (Read)* | =arc_swap::ArcSwap<AppState>= | Provides lock-free, zero-contention state inspection during UI repaints. |
| *State Engine → UI (Signal)* | =tokio::sync::broadcast= | Emits lightweight triggers (=EngineSignal::StateUpdated=) to prompt GUI repaints. The UI is not the only subscriber: the boot-pull waiter also subscribes (=wait_for_boot_pull= in the boot ceremony, ADR 0014), and the bus legally runs with zero subscribers — a plain daemon's publishes are fire-and-forget (the send result is deliberately ignored). |
| *UI/CLI → State Engine* | =tokio::sync::mpsc= + =oneshot= | =EngineEnvelope::Execute= carries a =StateCommand= payload with an optional oneshot receipt (typed =Result<CommandOutcome, ExecuteError>=; a received reply implies durability). =EngineEnvelope::Flush= is the reply-less dispatch durability barrier (CLI exit). |
| *State Engine → Sync Actor* | =tokio::sync::mpsc= | =SyncCommand= nudges: =SyncNow= (forwarded iff an accepted batch enqueued an op, or on =RequestSync= / =NetworkRestored=). The actor dedupes =SyncNow= while a cycle runs. There is no targeting message: the retired =SetBoard= pull-target command is gone — each sync actor derives its per-cycle board set from the persisted connector-tagged bindings (the broadcast =SyncNow= is the only nudge). |
| *Sync Actor → State Engine* | =tokio::sync::mpsc= | =SyncReport::{Completed, Failed}= ingestion through the conflict pipeline (ADR 0007's evidence-then-verdict: =Completed= carries snapshot + validators + pushes + =read_at=; =Failed= carries the pushes that landed before the abort). |
| *Sync Actor → Everyone* | =tokio::sync::broadcast= | Produces =SystemEvent::ConnectorLost= / =ConnectorRestored(ConnectorId)= for its own connector (episode-edge: exactly once per offline episode, report-then-restore order) and consumes only =Shutdown= from the same channel. The global =NetworkLost= / =NetworkRestored= names belong to the app-layer authority (next row). |
| *App authority → Everyone* | =tokio::sync::broadcast= | The all-down authority (=taskboard-app/src/authority.rs=): an app-layer counting task seeded from the configured connector module set and updated by the registry's attach/detach hooks. It subscribes the system broadcast and emits the global =SystemEvent::NetworkLost= on the all-down crossing (the last up connector flips down) and =NetworkRestored= on the first up — so one connector down while others respond is normal operation, not an outage. Single-connector installs keep the old semantics exactly. |
| *Sync Actor → State Engine (reads)* | domain port =SyncStateReader= | =EngineEnvelope::ReadState= envelope behind the port: the cycle reads outbox, bindings, and validators via the engine, never direct SQL (ADR 0005/0007). |
| *State Engine → Notifier* | =tokio::sync::mpsc= | =Notification= payloads (capacity 64, =NOTIFIER_CAPACITY=) consumed by the notifier task (=spawn_notifier=), which delivers them through the =NotificationSink= port (=LogSink= v1 and the daily-driver wave's =DesktopSink=, selected by =[reminders] sink= — ADR 0013). Delivery is durable-then-notify: delivery markers persist before any send and a failed batch fires nothing; =send= (not =try_send=) backpressures the tick; the consumer exits when the engine's exit closes the channel. Derived edge: =docs/flow_model.org= E-20 / actor NTF. |
| *Actors ↔ Actors* | =tokio::sync::mpsc= | Direct point-to-point command delivery between backend actors (e.g., State Engine → Storage via the =TaskRepository= port adapter). |
| *System Notifications* | =tokio::sync::broadcast= | Broadcasts global status changes (=SystemEvent::NetworkLost=) to all interested actors. |
| *CLI ⇄ Daemon (local socket)* | =interprocess= local sockets + length-framed JSON | Transport-only reuse of =dispatch_line= (ADR 0012): the daemon serves the per-database socket (<db>.sock sidecar); a CLI invocation relays raw argv and prints the daemon's rendered ={code, out, err}= verbatim — byte-identical to the in-process dispatch. Versioned envelopes (v1); one request per connection; serial execution on one dispatcher task. |
| *Asynchronous Queries* | =tokio::sync::oneshot= | Embedded inside an =mpsc= message payload for direct, async request-response cycles. Payloads are pure domain types; the channel-bearing envelope is declared by the actor crate (payload/envelope split, ADR 0004). |
| *REPL loop ⇄ editor thread (disposition)* | =tokio::sync::mpsc= + embedded =oneshot= (ADR 0014) | The per-line handshake: the editor thread delivers one =LineEvent=, then awaits the loop's =Disposition= (=Next=, or =Prompt{label, kind, reply}= for a follow-up read). Masked reads (=rpassword=) run on the reader thread; answers ride the oneshot and never enter history or completion. Capacity-1 channels keep the alternation strict — the race-free property. |
| *Session ⇄ core (connector ceremonies)* | =App::attach_connector= / =App::detach_connector= + config refresh (ADR 0014) | An in-session =connect= line runs the shared ceremony through the session's prompt reader, refreshes the session config through the boot resolution, detaches any live connector, and attaches a fresh one from the refreshed config; =logout= is the mirror (local teardown → detach → refresh). Attach/detach are per-name against the connector registry (=ConnectorNameInUse= names the offender when the name is already live). Verb bodies are frontend-agnostic functions the Phase 7 GUI reuses. |

Channel wiring is *handed over by bootstrap; constructed in the owning
spawn/hand-over functions*. =bootstrap()= itself constructs the system
broadcast, both sync =mpsc= pipes, and the notifier feed; the engine
inbox and signal bus are constructed in =spawn_state_engine=
(taskboard-state), the storage inbox in =spawn_storage_actor=
(taskboard-storage-sqlite), the UI-command channel in =run_desktop=
(=taskboard_app::ui=), the IPC inbound + stop watch in
=spawn_server=, and the REPL handshake pairs in the REPL's
reader/prompt setup. Actors receive their halves as injected
constructor arguments and never construct channels between themselves
— every off-bootstrap constructor sits in a spawn/hand-over function
the app layer calls (ADR 0008).

** Vocabulary after the multi-board wave

The multi-board wave (ADR 0010 as amended, 2026-10-20) moved the four
inter-actor vocabularies from "the one bound board" to N boards across
N named connectors. The post-wave shape, one row per vocabulary:

| Vocabulary | Shape after the wave |
|---+---+---|
| Commands (=StateCommand=) | The board-scoped arms carry =board: BoardId= (=CreateStack=, =CreateLabel=, =RenameBoard=, =SetBoardColor=, =SetBoardArchived=, =DeleteBoard=, =ResetBoard=, =BindBoard=, plus =UnbindBoard { board }= and =ReconcileByTitle { board }= from the ceremonies); =CreateBoard= carries none — its single-live-board refusal is lifted, so it always mints. Task/stack/label-scoped commands stay id-addressed. |
| Outbox ops (=LocalOp=) | Unchanged — already board-addressed / entity-scoped; the push side filters to the boards owned by the pushing connector. |
| =CommandError= | Removed =NoBoard= and =BoardExists=; added =UnknownBoard(BoardId)= and =BoardDeleted(BoardId)=; =BoardAlreadyBound { board, bound }= names both sides; =RemoteBoardInUse { remote, board }= refuses adopting a remote another board already owns. |
| Status payloads | =AppState.sync= is the per-board =SyncStates(BTreeMap<BoardId, SyncStatus>)= map with the =aggregate()= fold; =SyncCommand= is ={SyncNow, Detach}= (=SetBoard= retired); =SyncReport= is unchanged (already per-board snapshots). |

Connector identity is one name end-to-end: config =name= →
=ConnectorId= (a domain newtype) → the connector tag on
=RemoteBoardBinding= → the registry key (=SyncActor.id=) → the module
id (=ConnectorModule::id=) → the CLI's =--connector= values. Board
attribution in status surfaces stays *derived from bindings, never
stored*.

* Cargo Workspace Topology

To enforce strict boundary checks at compile time and accelerate build
speeds, the project is structured as a Cargo workspace with explicit
dependency hierarchies.

** Crate Roles & Dependencies

1. *taskboard-domain* — Pure data types (the canonical =Board= / =Stack= /
   =Task= / =Label= entity set with per-field write clocks; =Project= is
   superseded by =Board= and =UserPreferences= is deferred), inter-actor
   message payloads (=StateCommand=, =SystemEvent=, =SyncCommand=,
   =SyncReport=), the =ConnectorId= config-name newtype, the
   persistence port (=TaskRepository=), and the pure
   sync conflict policy (=apply_sync_report=, ADR 0004). Board
   bindings carry their owning connector (=RemoteBoardBinding
   { connector, board }=), and the runtime state's =AppState.sync= is
   the per-board =SyncStates(BTreeMap<BoardId, SyncStatus>)= map with
   the =aggregate()= fold — attribution stays derived from bindings,
   never stored. The policy is
   executed by the *state engine*, never by the sync actor.

   The daily-driver wave grew the entity/message inventory: the
   *task field family* — =Task.scheduled= / =Task.effort= /
   =Task.importance= / =Task.urgency= with their four =TaskClocks=
   slots (=Effort= is the u64-seconds newtype; =Importance= and
   =Urgency= are two distinct five-level enums whose declaration
   order is severity), each slot a =TaskChanges= double option
   (=Some(None)= clears and stamps) — and the exported =TASK_FIELDS=
   lockstep manifest assigning every mergeable field its clock set,
   its =FieldFamily::{Native, AppData}= sync lane, and its =TaskChanges=
   slot (four homes pin it: the domain pipeline tests, the storage
   schema tests, the appdata modeled-key set, and the engine's
   manifest op routing). New pure modules: =days.rs=
   (=day_window=, =today_sections= — fixed-offset day arithmetic;
   consumers receive time and offset as data), =find.rs= (the
   class-ordered fuzzy ranking core behind the =find= verb and the
   palette — the crate-swap firewall), =appdata.rs= (the versioned
   per-board document codec: embedded-clock union + snapshot-absence
   GC, verbatim unknown-content preservation, =scheduled= as the
   fourth modeled key), and =capabilities.rs= (=DeckFeatures= +
   =flags_for= — the codebase's only version switch).
   =merge.rs= carries =fold_task_app_data= and =fold_reminder_rules=
   (the document fold);
   =reminders.rs= carries =AdhocAlarm= / =ReminderRef::Adhoc= /
   =ReminderAnchor{Task|Alarm}=, the tick's alarms pass and the
   settlement prune; =CaptureTask= carries the quick-capture intent
   with its Inbox/Backlog resolution rules; the reminder verbs are
   =AddReminderRule= / =RemoveReminderRule= / =ClearReminderRules=
   (=SetReminderRule= retired; N-rule additive); and
   =SyncReport::Completed= carries =app_data: AppDataEvidence=
   (=Document | Absent | Unreadable{FormatTooNew|Transport|Decode|
   ForeignBoard}=) per board. The purity sentence stands: the sidecar
   codec is pure serde + pure functions (=serde_json= for verbatim
   preservation is its only new dependency).

   Dependencies: minimal (see the crate's =Cargo.toml= for the exact
   set — no I/O, no
   subscriber, no runtime). Zero UI, network, database, or
   async-runtime dependencies; async ports return a
   hand-rolled =BoxFuture=. Channel-bearing envelopes (e.g. a =Flush=
   barrier wrapping =oneshot::Sender=) live in the actor crates that own
   the channels — domain owns only the pure payloads.

2. *taskboard-state* — Single source of runtime truth (ADR 0006). Runs
   the State Engine actor: a sequential command loop over the domain's
   pure transition functions (=plan_command= for local commands,
   =apply_sync_report= for sync ingestion). Memory advances only by
   interpreting the action batches that were durably applied through the
   =TaskRepository= port (consumed as =Arc<dyn TaskRepository>—
   production wires the sqlite actor via a port adapter); after each
   interpreted batch it publishes the =AppState= projection through
   =ArcSwap<AppState>= and broadcasts =EngineSignal::StateUpdated=.
   Inbox: =EngineEnvelope::{Execute (oneshot receipt), Flush (durability
   barrier)}=; it also ingests =SyncReport=s and =SystemEvent=s, and
   forwards =SyncNow= nudges to the sync actor. =SyncReport= ingestion
   re-keys the per-board sync map by the report's board; the
   =SystemEvent::ConnectorLost(c)= arm scopes =go_offline= to =c='s
   boards (derived from the engine's own binding tags) while
   =ConnectorRestored(c)= forwards the nudge. Scheduling rides a
   =sleep_until= select *tick arm* (first tick immediate, so reminders
   left undelivered before a shutdown fire on the next boot; disarmed
   while the engine drains) that runs the pure reminder evaluator over
   =EngineCore=, persists delivery markers, interprets, publishes, and
   only then notifies (ADR 0013). The engine's *sidecar half* (the
   daily-driver wave): =apply_sync_report= runs =fold_task_app_data=
   and =fold_reminder_rules= over the downloaded document after the
   task merge loop, behind the self-clobber guard mirror (=UpdateAppData=
   intents set all app-field flags + rules; the fold copies values
   *and* embedded clocks); per-board sidecar health is derived onto
   =SyncStatus.sidecar= (memory-only, from the report's
   =AppDataEvidence=); op routing is driven from the =TASK_FIELDS=
   manifest (every manifest row routes through its declared lane); the
   tick runs the alarms pass over =AdhocAlarm=s and the settlement
   prune after snooze compaction; and the =CaptureTask= handler
   resolves the app-global Inbox board (created/adopted unbound,
   canonical-first) or the board-directed Backlog. Command *semantics*
   (rejections, no-ops, cascades) live in the domain; this crate owns
   channels, publishing, and sequencing only. Dependencies: see the
   crate's =Cargo.toml=.

3. *taskboard-sync-nextcloud* — The sync actor (ADR 0007): a scheduled
   cycle that reads the engine's persisted state through the domain's
   =SyncStateReader= port (never direct SQL, ADR 0005), pushes the
   coalesced outbox via the pure =plan_pushes= planner + push executor
   (binding overlay, fetch-before-write, typed error classification;
   the ownership filter plans only the boards bound to *this*
   connector), pulls every board in its derived owned-board set —
   recomputed each cycle from the persisted connector-tagged bindings
   (tombstoned boards drain out; foreign-tagged boards are excluded) —
   each through three conditional reads into a complete
   =RemoteBoardSnapshot= (both stack listings; per-card detail
   refresh) with per-board pull-cache keys (no cache-clear on rebind;
   unchanged boards stay cheap via per-board validators), and reports
   =SyncReport=s with evidence-then-verdict semantics. Owns the
   per-connector offline FSM: broadcasts
   =SystemEvent::ConnectorLost/ConnectorRestored= for its own
   connector, failure backoff, cycle-in-flight dedupe; binding happens
   by adoption in the engine, and the broadcast =SyncNow= is the only
   nudge it consumes. The connector's *sidecar half* (the daily-driver
   wave): a one-per-actor-lifetime capability probe
   (=GET ocs/v2.php/cloud/capabilities=, =deck.version= →
   =DeckFeatures=, conservative fallback) gates card conversion
   (=scheduled= encodes as wire =startdate= only when native); the
   attachment-create form carries the additive =data= field
   unconditionally and the echo decode folds
   =extendedData.info.filename= into the stored filename (the
   Deck 1.17.5 parity wire changes); the *anchor ceremony* discovers
   each board's app-data carrier by exact-title
   =([taskboard] app-data)= scan of active+archived cards, confirms by
   detail read, picks newest-stamp-then-lowest-id, adopts exactly one
   unconfirmed candidate, and creates lazily actor-side; documents
   download during the pull and flush between pull and report as a
   read-modify-write union (lane GC + snapshot-absence GC; rebuild
   mode re-seeds from all local entries; restore-then-replace for
   tombstoned carriers); the D-S7 fences classify
   format-too-new/corrupt/foreign/moved-card evidence without
   re-encoding; =LoopState= keeps the in-memory document + feature
   caches; and =plan_pushes= emits one document push per board, after
   its =CreateTask= groups. Stateless across
   restarts except the injected =DeckClient=. Dependencies: see the
   crate's =Cargo.toml=.

4. *taskboard-storage-sqlite* — Manages local SQLite disk persistence.
   Ensures the app boots immediately with cached data if network
   connectivity is lost. Normalized schema (boards/stacks/tasks/labels,
   =task_labels= join, =outbox=, =sync_metadata=, the per-board
   =sync_status= table — migration 0006 rebuilt the v0.1.x singleton
   and also added the =boards.connector= binding tag, whose legacy
   =NULL= decodes as the spawn-time default connector
   (the =default_connector= parameter of the storage =open= /
   =open_with=, handed the config-resolved id at boot);
   upserts write the tag, so legacy NULLs are read-only relics),
   plus the four reminder tables of migration 0004: =reminder_rules= /
   =reminder_deliveries= / =reminder_snoozes= / =reminder_muted=,
   ADR 0013), the daily-driver wave's two additive migrations —
   *0007* (the four task-field value columns + four epoch-defaulted
   clock columns so pre-migration rows keep the remote-wins merge
   behavior, plus =reminder_rules.updated_at=, the rule write clock
   the codec reads and writes since chunk 4 of the wave) and *0008*
   (the =adhoc_alarms= table on the 0004 conventions) —
   applied at boot from embedded migrations; WAL + =synchronous=NORMAL= on
   a single connection; =SqliteTaskRepository= implements the domain's
   =TaskRepository= port (one transaction per batch) behind the
   =StorageCommand= actor inbox (=StorageHandle=, oneshot replies —
   ADR 0005). Compile-time checked =query!= SQL against the committed

   the L1 widget / L2 composition / L3 view component layering
   under =ui/=, and =presentation= (pure display helpers reusing the

6. *taskboard-app* — The bootstrap library (ADR 0008) plus the thin
   =taskboard= binary. The library owns =config= (figment hierarchy
   defaults → =taskboard.toml= → =TASKBOARD_*= env, strict tables —
   secrets in TOML cannot decode; the config *file* resolution order is
   =--config= > =TASKBOARD_CONFIG= > the XDG candidate
   =$XDG_CONFIG_HOME/taskboard/taskboard.toml= when it exists >
   =./taskboard.toml=, absent files tolerated; the =[reminders]=
   table — =enabled= / =tick_secs= / =default_before= / =sink=
   (=?auto|log|desktop=; =auto= resolves by =AppMode= at boot via
   =notifications::resolve_sink=) — and the =[preferences]= table
   (=?day_start_time=, device-local, never synced) are validated
   with typed rejections (=invalid-duration= /
   =invalid-day-start-time=), ADR 0013), the kiosk wave's =[kiosk]=
   table (=fixed_board= + the optional =[kiosk.rotation]= — typed
   errors for every invalid value, =resolve_fixed_board='s pin
   matrix) and =[web]= table (=enabled= / =bind= / =refresh_secs= /
   =token=, the dashboard's deployment profile) are validated the
   same way, =secrets= (the =CredentialStore=
   port with the keyring and env stores plus the kiosk wave's
   encrypted-file store, config-selected, no silent
   fallback; redacting =AppPassword=), =web= (the dashboard server:
   routes / render / token — the hyper accept loop on the daemon
   lifecycle), =bootstrap=: one async fn
   that wires the whole channel graph (the system broadcast, both sync
   pipes, and the notifier feed are constructed here; the engine,
   storage, UI-command, IPC, and REPL channels are constructed inside
   their owning spawn/hand-over functions, all called from here —
   ADR 0007's handoff note; under the resolved =standalone= backend the
   connector set is empty and no sync actor is spawned — the channel
   halves are dropped and the engine sees the closed-channel world it
   already handles, ADR 0010), =connectors= (the named connector
   registry loop over the configured =[[sync.connectors]]= entries:
   each resolves to a =ConnectorModule= — the app-layer module trait
   of ADR 0010's amended split, domain vocabulary + app module trait,
   =dyn=-dispatched with one implementation today (nextcloud) — that
   spawns its sync actor with its =ConnectorId=; attach/detach are
   per-name) and =authority= (the all-down counting task emitting the
   global =NetworkLost/NetworkRestored= on the episode-edge crossings,
   =taskboard-app/src/authority.rs=), and returns the =App= handle
   shared by every frontend, =lockfile= (the per-database instance lock — an
   OS-released advisory lock on a =<db>.lock= sidecar acquired before
   the db open, ADR 0009), =notifications= (the =NotificationSink=
   port carrying both sinks — =LogSink= v1, one log line per
   delivery, and the daily-driver wave's =DesktopSink=
   (=notify-rust= 4.18.2: passive toasts; a failed delivery is a
   logged error, never retried, never fallback-sent), selected by
   =[reminders] sink= with =auto= resolving by =AppMode= at boot,
   ADR 0013), and =commands=
   (ADR 0009): the operator
   CLI's typed handlers — =connect= (introduces a connection; =login=
   is its deprecated alias, ADR 0014), =logout=, =boards= (list/select/
   create/publish/rename/color/archive/unarchive/delete/reset/unbind/
   reconcile, plus the REPL-only =boards use= — the session's board
   selection; =--board= targets one of N on the board-scoped verbs,
   =--connector <name>= scopes =boards list/select/publish= and
   =sync=), =stacks= (add/rename/delete/move), =tasks=
   (list/add/done/move/edit/delete/label/unlabel/remind — the
   =remind= mode flags =--before=/=--list=/=--clear=/=--off=/=--on=
   plus the =--remove= rule selectors, ADR 0013; =edit= carries the
   daily-driver wave's field flags =--scheduled=/=--effort=/
   =--importance=/=--urgency= (=?none= clears) beside =--due=;
   =move= gains =--board= as a stack-selector pre-filter; the app
   layer refuses rename/delete on the app-data anchor card with the
   typed =AnchorTaskReserved= (=anchor-task-reserved=)), the
   top-level =find= verb (=?--type task|stack|board=,
   =?--limit=), =capture= (the quick-capture intent), =timers=
   (add/list/cancel — =--in=/=--at=, device-local), =labels=
   (list/add/edit/delete), =sync=, =status= (the additive
   per-connector =connectors= array and flat per-board =boards= array
   beside the unchanged aggregate =sync= field; the kiosk wave added
   the cumulative per-board sync counters and the handle-side
   =engine= object (the commands / rejections / publish-signal
   activity counters), =config print= — with the =--json=
   output contract (typed projections on stdout, kebab-case error
   envelopes on stderr). Task selectors cascade exact uuid → unique
   ≥8-char prefix → exact title; destructive verbs are
   confirmation-free (scripting-first) with idempotent repeats; board
   titles are locally editable (the field-wise title merge of the ADR
   0004 amendment). =main.rs= is dispatch + exit codes only.
   =App::shutdown()= is the graceful sequence (flush → =Shutdown=
   broadcast → bounded actor joins with the engine's linger-drain →
   storage join). =repl= (ADR 0011): the interactive session frontend —
   bare =taskboard= on a TTY opens a parted-style shell over *one*
   booted core (boot-once, one lock epoch, graceful shutdown at
   =exit=/Ctrl-D); each line is shell-word-split, parsed as one CLI
   invocation (=Cli::try_parse_from=), and routed by
   =dispatch_line= through the same =*_on(&App)= verb bodies the
   one-shot wrappers call; =connect=/=login=/=logout= are intercepted
   by the session loop as ceremonies (ADR 0014: config refresh +
   per-name connector attach/detach against the running core, over the
   connector registry), =boards use= sets =ReplSession.current_board=
   (the session's board selection for later board-scoped lines), and
   the daemon
   IPC server refuses them as terminal-bound before dispatch. The
   rustyline editor lives on a dedicated thread streaming =LineEvent=s
   through a bounded channel and answering the loop's per-line
   =Disposition= handshake (masked reads included), so no async
   runtime worker ever blocks on stdin. =ipc= (ADR 0012): the daemon
   IPC frontend — the third frontend over the shared seam. The server
   binds the per-database socket (=<<db>.sock= sidecar, stale-artifact
   recovery, unix 0600), accepts connections concurrently, and executes
   requests serially on one dispatcher task (engine fairness); the
   client relays rendered ={code, out, err}= verbatim with typed
   =NoDaemon=/=IpcTransport=/=IpcVersion= failures; =route_for_ipc=
   picks each verb's transport lane (Local / IpcOrLocal / IpcOnly) and
   =status=/=daemon stop= are the operator verbs over the wire.
   The socket is optional: =[ipc] enabled= (or =daemon --no-ipc=,
   #194) skips =spawn_server= and the daemon runs lock + actors + web
   with no command surface; the operator verbs degrade to their typed
   no-socket outcomes and the kiosk headless fallback inherits the
   same shape.
   =ui= (ADR 0015, ADR 0016): the GUI lifecycle — D4 bare-invocation
   routing (=mode = "desktop"= boots the Slint GUI regardless of TTY;
   =AppMode= is frontend selection, so only =Daemon=+TTY falls to
   the REPL; a non-TTY =Daemon= launch inside a graphical session
   (display env present — ADR 0015 amendment) boots the GUI instead
   of a silent headless daemon; bare =kiosk= boots the appliance
   (display-gated with a loud headless fallback, TTY-independent —
   ADR 0016); otherwise the daemon lifecycle), the
   UI-command
   forwarder (=spawn_ui_command_forwarder= over the =CommandSink=
   trait), and =resolve_ui_settings= (the figment =[ui]= table into
   typed =UiSettings=; keymap findings surface as startup warnings
   and never block start). The =[ui]= config surface: =scale=
   (0.5–3.0, typed-validated) and =keymap.preset= /
   =keymap.overrides=.
   Dependencies: all workspace
   crates plus the manifest's set (see the crate's =Cargo.toml=;
   =keyring= rides platform features via target-specific deps, and the
   optional =console-subscriber= feature gates =tokio-console=
   support).

* Versioning

The project uses a single global semantic version shared by all crates:

#+begin_example
taskboard v0.1.0
├── crates/taskboard-domain         @ 0.1.0
├── crates/taskboard-state          @ 0.1.0
├── crates/taskboard-sync-nextcloud @ 0.1.0
├── crates/taskboard-storage-sqlite @ 0.1.0
├── crates/taskboard-ui-slint       @ 0.1.0
└── crates/taskboard-app            @ 0.1.0
#+end_example

The version is defined once in =[workspace.package] version= in the root
=Cargo.toml=; every member crate inherits it via =version.workspace = true=.
Releases are cut exclusively with =./scripts/bump_version.sh
<major|minor|patch>= (see =docs/coding_guidelines.org=). The numbers in
the example tree are illustrative — =[workspace.package] version= in
the root manifest is the only truth.
